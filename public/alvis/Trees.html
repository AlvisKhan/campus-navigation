Trees, from first node to interview-ready

A tree is nothing but a linked list that learned to branch. Everything below is built in C++, and every traversal is chosen specifically to make Stack and Queue problems feel obvious afterward — because that's literally what a traversal is.

01 What is a Tree

A tree is a hierarchical structure of nodes connected by edges, with no cycles. One node is the root; every other node has exactly one parent and zero or more children. Nodes with no children are leaves.

10 is the root. 5 and 15 are its children (and each other's siblings). 2, 7, 20 are leaves. The height of a node is the longest path down to a leaf (root here has height 2); the depth of a node is its distance from the root.

02 Types of Trees You'll Actually Meet

Binary Tree

Each node has at most 2 children — left and right. No ordering rule.

Binary Search Tree (BST)

A binary tree where left subtree < node < right subtree, always. Enables fast search.

Complete Binary Tree

Every level full except possibly the last, filled left to right. Basis of heaps.

Balanced Tree

Height stays O(log n) — e.g. AVL, Red-Black. Keeps operations fast.

Almost every interview question builds on the plain Binary Tree and BST, so that's our focus.

03 The Node, in C++

Everything starts with one struct. Memorize this shape — it's the atom of every tree problem.

struct Node {
    int data;
    Node* left;
    Node* right;
    Node(int val) : data(val), left(nullptr), right(nullptr) {}
};

// building the tree from the diagram above, by hand
Node* root = new Node(10);
root->left        = new Node(5);
root->right        = new Node(15);
root->left->left   = new Node(2);
root->left->right  = new Node(7);
root->right->right = new Node(20);
Why a pointer to Node, not a Node? A tree's size isn't known ahead of time — pointers let each node live independently on the heap and link dynamically, exactly like a linked list's next, just doubled into left/right.

04 DFS Traversals — Preorder, Inorder, Postorder

Depth-first means: go as deep as possible before backing up. The three orders only differ in when you visit the node relative to its children.

Click through the tree below and watch each order unfold:

// Node -> Left -> Right. Use to copy/serialize a tree.
void preorder(Node* root) {
    if (root == nullptr) return;
    cout << root->data << " ";   // visit
    preorder(root->left);
    preorder(root->right);
}
// Left -> Node -> Right. On a BST, this prints sorted order.
void inorder(Node* root) {
    if (root == nullptr) return;
    inorder(root->left);
    cout << root->data << " ";   // visit
    inorder(root->right);
}
// Left -> Right -> Node. Use to delete a tree, post free children first.
void postorder(Node* root) {
    if (root == nullptr) return;
    postorder(root->left);
    postorder(root->right);
    cout << root->data << " ";   // visit
}

All three are O(n) time (visit every node once) and O(h) extra space for the recursion stack, where h is the tree's height.

05 Stack ↔ Trees: the recursion is a stack

The key insight: when you call preorder(root->left) recursively, C++ pushes a stack frame. Recursive DFS is secretly using the call stack as its data structure. Replace the call stack with your own std::stack, and you get iterative DFS — the classic building block for stack questions.
// Iterative preorder — explicit stack does what the call stack did
vector<int> preorderIter(Node* root) {
    vector<int> result;
    if (!root) return result;
    stack<Node*> st;
    st.push(root);
    while (!st.empty()) {
        Node* cur = st.top(); st.pop();
        result.push_back(cur->data);
        // push right FIRST so left gets popped (visited) first
        if (cur->right) st.push(cur->right);
        if (cur->left)  st.push(cur->left);
    }
    return result;
}

This is exactly the pattern behind "evaluate expression tree", "flatten binary tree", and half of LeetCode's stack tag. Once you see recursion = implicit stack, converting any recursive tree function into an iterative one is mechanical: whatever you'd push onto the call stack (the next thing to process), push it onto a real std::stack instead.

06 BFS — Level Order Traversal

Where DFS goes deep first, BFS goes wide: visit every node at depth 0, then depth 1, then depth 2… This needs a queue, because a queue processes things in the order they were discovered (FIFO) — same order the levels were discovered.

vector<vector<int>> levelOrder(Node* root) {
    vector<vector<int>> result;
    if (!root) return result;
    queue<Node*> q;
    q.push(root);
    while (!q.empty()) {
        int sz = q.size();          // nodes in THIS level
        vector<int> level;
        for (int i = 0; i < sz; i++) {
            Node* cur = q.front(); q.pop();
            level.push_back(cur->data);
            if (cur->left)  q.push(cur->left);
            if (cur->right) q.push(cur->right);
        }
        result.push_back(level);
    }
    return result;
}

On the same tree, level order visits: 10 → 5,15 → 2,7,20

07 Queue ↔ Trees: the "snapshot the size" trick

The key insight: the line int sz = q.size(); before the inner loop is the single most reused trick in queue-based tree problems. It freezes "how many nodes are in the queue right now" so the inner loop processes exactly one level, even though you keep pushing next-level children into the same queue mid-loop.

Master that one snapshot-the-size pattern and you can solve: zigzag level order, right-side view, level averages, min depth via BFS, and any "process layer by layer" queue question — they're all this loop with one extra tweak.

08 Binary Search Tree — Search & Insert

A BST layers ordering on top of the shape you already know: at every node, everything smaller goes left, everything bigger goes right. That one rule makes search O(log n) on a balanced tree, instead of O(n).

Node* insert(Node* root, int val) {
    if (root == nullptr) return new Node(val);
    if (val < root->data) root->left  = insert(root->left, val);
    else                  root->right = insert(root->right, val);
    return root;
}

bool search(Node* root, int val) {
    if (root == nullptr) return false;
    if (root->data == val) return true;
    return val < root->data ? search(root->left, val)
                              : search(root->right, val);
}
Remember section 04? Run inorder() on any BST and the output is always sorted ascending — left, then node, then right means smaller-node-bigger, level after level. That's a free sanity check when debugging a BST.

09 Height, Diameter & Balance

Height is computed bottom-up: a leaf's subtree has height 1 (or 0, pick a convention and stay consistent), and every other node is 1 + max(leftHeight, rightHeight). This is a postorder shape — you need both children's answers before you know your own.

int height(Node* root) {
    if (!root) return 0;
    return 1 + max(height(root->left), height(root->right));
}

Diameter — the trap question

Diameter is the longest path between any two nodes, and it does not have to pass through the root. The naive approach recomputes height at every node — O(n²). The trick: compute height and update a running diameter in the same postorder pass.

Gold path: 2 → 5 → 10 → 15 → 20, a diameter of 4 edges — it passes straight through the root here, but in general it might not.

int diameter = 0;
int heightAndDiameter(Node* root) {
    if (!root) return 0;
    int lh = heightAndDiameter(root->left);
    int rh = heightAndDiameter(root->right);
    diameter = max(diameter, lh + rh);   // path through THIS node
    return 1 + max(lh, rh);
}

Balanced Check

// naive: O(n²). Better: fold the check into the height computation,
// returning -1 as a sentinel the moment any subtree is unbalanced.
int checkHeight(Node* root) {
    if (!root) return 0;
    int lh = checkHeight(root->left);
    if (lh == -1) return -1;
    int rh = checkHeight(root->right);
    if (rh == -1) return -1;
    if (abs(lh - rh) > 1) return -1;
    return 1 + max(lh, rh);
}
bool isBalanced(Node* root) { return checkHeight(root) != -1; }
Pattern to remember: "compute one thing bottom-up while updating a global/outer answer along the way" solves diameter, balance-check, max path sum, and more. It's postorder DFS wearing different clothes.

10 Lowest Common Ancestor (general Binary Tree)

Not a BST this time — no ordering to exploit. The idea: search left and right for the two target nodes; if one is found on each side, the current node is the split point, i.e. the LCA.

LCA(2, 7) = 5 — the deepest node that has both 2 and 7 somewhere below it.

Node* lowestCommonAncestor(Node* root, Node* p, Node* q) {
    if (!root || root == p || root == q) return root;
    Node* left  = lowestCommonAncestor(root->left, p, q);
    Node* right = lowestCommonAncestor(root->right, p, q);
    if (left && right) return root;   // found one on each side
    return left ? left : right;        // both were on the same side
}

11 Invert & Symmetric — the classic swap tricks

Invert a Binary Tree

Node* invert(Node* root) {
    if (!root) return nullptr;
    swap(root->left, root->right);
    invert(root->left);
    invert(root->right);
    return root;
}

Check Symmetric

bool mirror(Node* a, Node* b) {
    if (!a && !b) return true;
    if (!a || !b || a->data != b->data)
        return false;
    return mirror(a->left, b->right)
        && mirror(a->right, b->left);
}

Both are the same idea as everything above: express the answer for a node in terms of the answer for its children, and let recursion (the call stack, from Section 05) do the bookkeeping.

12 Interview Pattern Cheat-Sheet

"Level by level"

BFS + size-snapshot queue trick. → right side view, zigzag, min depth, level averages.

"Bottom-up combine"

Postorder, return a value built from both children. → height, diameter, balance, max path sum.

"Path from root"

Preorder, carry a running list/sum down as a parameter. → root-to-leaf paths, path sum, longest path.

"Ordering shortcut"

Exploit BST's left<node<right. → LCA in BST, validate BST, kth smallest, closest value.

"Iterative with stack"

Explicit std::stack replaces recursion. → inorder/preorder without recursion, flatten tree.

"Two-node search"

Search both subtrees, combine at the split. → LCA in general binary tree.

14 Practice Set — do these in order

1. Maximum Depth of a Binary Tree

Return 1 + max(depth(left), depth(right)), base case nullptr → 0. Pure recursion, no stack/queue needed — warm-up.

2. Iterative Inorder Traversal (uses Section 05)

Push all left children onto a stack until null, pop & visit, then move to the popped node's right child and repeat. Harder than preorder because "visit" happens in the middle, not first.

3. Binary Tree Right Side View (uses Section 07)

Do level order BFS; in each level's inner loop, the last node processed (i == sz-1) is the one visible from the right.

4. Validate a Binary Search Tree

Don't just compare each node to its children — pass down a valid (min, max) range and shrink it as you recurse.

5. Lowest Common Ancestor in a BST

Use the ordering: if both values are less than root, go left; both greater, go right; otherwise root is the split point — that's your answer.

6. Zigzag Level Order Traversal

Same queue loop as Section 06/07, but reverse alternating levels (track a boolean that flips each pass, or push into a deque).

7. Diameter of a Binary Tree

Straight from Section 09 — one postorder pass, update a global/outer diameter as lh + rh at every node while returning height upward.

8. Kth Smallest Element in a BST

Inorder traversal on a BST is sorted — do an iterative inorder (Section 05's stack trick) and stop the moment you've popped k nodes.

9. Serialize and Deserialize a Binary Tree

Preorder-with-nulls: serialize with preorder, writing a sentinel (e.g. "#") for every null child. Deserialize by consuming that same string with a preorder-shaped recursive rebuild — a nice test of Sections 04 and 05 together.
