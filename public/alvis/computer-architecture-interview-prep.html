01

Architecture Basics

Q1. What is computer architecture, and how is it different from computer organization?

Architecture is the "what" — the programmer-visible part: instruction set, addressing modes, data types, registers exposed to software. Organization is the "how" — the actual hardware implementation: control unit design, bus structure, memory technology used to realize that architecture.

Interview one-liner: "Architecture is the contract with the programmer; organization is how the hardware honours that contract." Two CPUs with the same architecture (e.g. two different x86 chips) can have very different organizations.

Q2. Explain the Von Neumann architecture. What is the "Von Neumann bottleneck"?

A Von Neumann machine stores program instructions and data in the same memory, accessed over a single shared bus. Core components:

  • CPU — ALU + control unit + registers
  • Memory — single unified address space for code and data
  • Input/Output — peripherals
  • Bus — connects everything, carries address/data/control signals

Because instructions and data share the same bus, the CPU cannot fetch an instruction and read/write data at the same time — this serialization is the Von Neumann bottleneck, and it's the main reason caches and pipelining exist.

Q3. How does Harvard architecture solve this? Where is it used today?

Harvard architecture uses separate memories and buses for instructions and data, so both can be fetched in the same cycle — no contention. Pure Harvard is rare in general-purpose CPUs (rigid, hard to load programs dynamically), but the idea survives as Modified Harvard: unified main memory, but split L1 instruction cache and L1 data cache — used in virtually every modern processor including those in Infosys's typical enterprise/embedded stack.

Q4. What is Flynn's Taxonomy? How does it classify processors?

Flynn's Taxonomy classifies architectures by how many instruction and data streams they process simultaneously:

ClassMeaningExample
SISDSingle Instruction, Single DataClassic single-core CPU
SIMDSingle Instruction, Multiple DataGPUs, vector/AVX instructions
MISDMultiple Instruction, Single DataRare — fault-tolerant systems
MIMDMultiple Instruction, Multiple DataMulticore CPUs, distributed systems

Interviewers like this because it connects nicely to a follow-up on GPUs vs CPUs: GPUs are SIMD-heavy (same operation across thousands of data elements), CPUs are MIMD (independent cores doing independent work).

Q5. Hardwired vs microprogrammed control unit — what's the difference?

  • Hardwired control unit — control signals are generated by fixed logic circuits (combinational + sequential logic). Very fast, but hard to modify — any change to the instruction set means redesigning the circuit. Common in RISC CPUs where instructions are simple.
  • Microprogrammed control unit — control signals come from a small internal program (microcode) stored in a control memory (ROM). Each instruction maps to a sequence of micro-instructions. Slower than hardwired, but flexible — new instructions can be added by updating microcode. Common in CISC CPUs.

Q6. What are the basic functional units of a CPU?

  • ALU (Arithmetic Logic Unit) — performs arithmetic (add, subtract) and logical (AND, OR, NOT) operations.
  • CU (Control Unit) — decodes instructions and generates control signals that orchestrate every other unit.
  • Registers — tiny, ultra-fast storage inside the CPU: PC (Program Counter), IR (Instruction Register), MAR/MBR (Memory Address/Buffer Register), Accumulator, general-purpose registers.
  • Bus interface — connects the CPU to memory and I/O.
02

CPU & Instruction Cycle

Q7. Walk me through the fetch-decode-execute cycle.

This is one of the most commonly asked questions — answer it as a numbered sequence:

  • 1. Fetch — PC holds the address of the next instruction; it's copied to MAR; the instruction is read from memory into MBR, then into the Instruction Register (IR); PC increments.
  • 2. Decode — the Control Unit interprets the opcode in IR and figures out what operation and operands are involved.
  • 3. Fetch operands — if needed, operands are read from registers or memory.
  • 4. Execute — ALU performs the operation.
  • 5. Store / Write-back — result is written back to a register or memory.

Then the cycle repeats for the next instruction. Mention that this is exactly what pipelining tries to overlap across multiple instructions (see Section 05).

This naturally sets up the memory hierarchy question in Section 06 — you can say "these three sit at the top of the memory hierarchy pyramid, trading capacity for speed."

Q9. What is clock speed, and does higher clock speed always mean a faster CPU?

Clock speed (GHz) is how many cycles per second the CPU executes. But actual performance depends on:

Execution Time = Instructions
               × Cycles per Instruction (CPI)
               × Clock cycle time

Known as the CPU performance equation. So a lower-clocked CPU with a better microarchitecture (fewer cycles per instruction, better pipelining, better branch prediction) can outperform a higher-clocked one — this is why raw GHz comparisons across different CPU families are misleading.

04

Addressing Modes

Q11. Name the common addressing modes with a one-line example each.

Immediate    : MOV R1, #5        ; operand is the value itself
Direct       : MOV R1, [1000]    ; operand is at memory address 1000
Indirect     : MOV R1, [[1000]]  ; address 1000 holds the address of operand
Register     : MOV R1, R2        ; operand is inside a register
Register Ind.: MOV R1, [R2]      ; R2 holds the memory address of operand
Indexed      : MOV R1, [R2+4]    ; base register + offset (great for arrays)
Base + Offset: used for stack frames, struct field access

Follow-up they often ask: "Why do we need so many?" — Answer: different modes trade off instruction size, flexibility, and speed. Indexed/base addressing is what makes array and struct access efficient without hardcoding every address.

05

Pipelining

Q12. What is pipelining and why does it improve throughput?

Pipelining overlaps the execution of multiple instructions by splitting the instruction cycle into independent stages, so while one instruction is being decoded, the next is already being fetched — like an assembly line. Classic 5-stage RISC pipeline:

IF  -> ID  -> EX  -> MEM -> WB
(Fetch)(Decode)(Execute)(Memory)(Write-back)

Without pipelining, each instruction needs 5 cycles serially. With pipelining, once the pipeline is full, one instruction completes every cycle — ideal speedup is close to 5x for a 5-stage pipe.

Cycle:     1    2    3    4    5    6    7
Instr 1:  IF   ID   EX   MEM  WB
Instr 2:       IF   ID   EX   MEM  WB
Instr 3:            IF   ID   EX   MEM  WB

Q13. What are pipeline hazards? Name the three types.

  • Structural hazard — two instructions need the same hardware resource at the same time (e.g. one memory port needed for both fetch and data access). Fixed by duplicating resources (separate I-cache/D-cache).
  • Data hazard — an instruction depends on the result of a previous instruction still in the pipeline. 
    ADD R1, R2, R3   ; R1 = R2 + R3
SUB R4, R1, R5   ; needs R1 (not written back yet!)
    Fixed by forwarding/bypassing (feed the ALU result directly to the next stage) or stalling.
  • Control hazard — caused by branches; the CPU doesn't know which instruction to fetch next until the branch is resolved. Fixed by branch prediction and speculative execution.
Fig 5 — Overlapping pipeline stages across instructions I1, I2, I3

Q14. Superpipelining vs superscalar — what's the difference?

  • Superpipelining — increase the number of pipeline stages (deeper pipeline) so each stage does less work and can run at a higher clock speed. More stages = more potential for hazards and higher misprediction penalty.
  • Superscalar — increase width instead of depth: duplicate execution units (multiple ALUs, load/store units) so more than one instruction can be issued and executed in the same cycle.

Modern high-performance CPUs (e.g. Intel Core, Apple M-series) combine both: deep pipelines and wide superscalar issue.

Q15. What is branch prediction, and what happens on a misprediction?

The CPU guesses which way a branch (if/loop condition) will go and speculatively fetches/executes down that path, instead of stalling until the condition is actually evaluated. If the guess is wrong, everything speculatively executed after the branch must be flushed from the pipeline and fetching restarts from the correct address — this "pipeline flush" is why mispredictions are expensive (can cost 10-20 cycles on deep pipelines).

06

Memory Hierarchy

Q16. Draw/describe the memory hierarchy and explain why it's shaped like a pyramid.

  ▲  Registers        <- fastest, smallest, $$$
  │  L1 Cache
  │  L2 Cache
  │  L3 Cache
  │  RAM
  ▼  SSD / Hard Disk  <- slowest, largest, cheap

Principle: as you go down, speed decreases, capacity increases, cost per byte decreases. It works because of locality of reference:

  • Temporal locality — recently used data will likely be used again soon (loop variables).
  • Spatial locality — data near recently accessed data will likely be accessed soon (array traversal).

Caches exploit both to keep frequently-used data close to the CPU, hiding the latency of slow main memory.

07

Cache Mapping & Performance

Q18. What are the cache mapping techniques?

  • Direct-mapped — each memory block maps to exactly one cache line. Simple, fast, but causes frequent conflict misses.
  • Fully associative — a block can go into any cache line. Fewer conflicts, but expensive to search (needs parallel comparators).
  • N-way set associative — middle ground: cache is split into sets, a block maps to one set but can occupy any of the N lines within it. Most real CPUs use 4-way to 16-way set associative caches.

Q19. How do you calculate Average Memory Access Time (AMAT)? Solve a quick example.

AMAT = Hit Time + Miss Rate x Miss Penalty

Example (frequently asked as a numerical): Hit time = 1 ns, Miss rate = 5%, Miss penalty = 100 ns.

AMAT = 1 + 0.05 x 100
     = 1 + 5
     = 6 ns

Follow-up: for multi-level cache, extend it —

AMAT = L1_HitTime + L1_MissRate × (L2_HitTime + L2_MissRate × L2_Penalty)
Fig 4 — Direct-mapped cache: several memory blocks compete for the same line

Q20. A system has 16 memory blocks and a 4-line direct-mapped cache. Which blocks map to line 0?

Direct-mapped index formula:

cache_line = block_number MOD number_of_lines
           = block_number MOD 4

Blocks 0, 4, 8, 12 all satisfy block MOD 4 == 0, so they all compete for Line 0. Only one of them can live in the cache at a time — loading block 8 while block 4 already occupies Line 0 evicts block 4. This repeated eviction of blocks that alias to the same line is exactly what causes conflict misses, and is the motivation for set-associative caches.

Q21. What is cache coherence, and what does the MESI protocol do?

In a multicore CPU, each core has its own private cache. If Core A and Core B both cache the same memory address and Core A updates its copy, Core B's cached copy becomes stale — this is the cache coherence problem. Every core must always observe a consistent view of memory.

MESI is a widely used coherence protocol where every cache line is in one of four states:

  • Modified — line is dirty, changed only in this cache, memory is stale.
  • Exclusive — line is clean, only this cache has it, matches memory.
  • Shared — line may exist in multiple caches, all clean and consistent.
  • Invalid — line is stale/unusable, must be refetched.

Cores snoop the bus and transition states on reads/writes so no core ever computes on stale data — this is what makes multicore programming safe from a hardware-memory standpoint.

Virtual Memory

Q23. What is virtual memory and why do we need it?

Virtual memory gives each process the illusion of having its own large, contiguous private address space, independent of how much physical RAM actually exists. Benefits:

  • Isolation — one process can't read/corrupt another's memory.
  • More usable memory — programs larger than physical RAM can run, using disk as overflow.
  • Simplifies programming — every process "thinks" it starts at address 0.

Implemented via paging: virtual address space is divided into fixed-size pages, mapped to physical frames using a page table. The CPU's MMU (Memory Management Unit) does this translation on every memory access, and a TLB (Translation Lookaside Buffer) caches recent translations so it doesn't need a full page-table walk every time.

Fig 6 — Paging: virtual address translated to a physical frame via the page table

Q24. Paging vs Segmentation — how do they differ?

PagingSegmentation
DivisionFixed-size pagesVariable-size logical segments (code, stack, heap)
Visibility to programmerInvisible — purely a memory-management trickVisible — matches how a programmer thinks about a program's structure
FragmentationInternal fragmentation (last page rarely full)External fragmentation (variable-size holes)
Address formPage number + offsetSegment number + offset

Many real systems (like x86) use both together: segmentation for logical structure, paging underneath for physical allocation.

Q25. What is a TLB, and what happens on a TLB miss?

The Translation Lookaside Buffer is a small, fast cache inside the MMU that stores recent virtual-to-physical page translations, so the CPU doesn't need to walk the (potentially multi-level) page table on every memory access. On a TLB hit, translation takes effectively zero extra cycles. On a TLB miss, the MMU/OS must walk the page table in memory to find the mapping — much slower — and then cache the result in the TLB for next time. High TLB hit rates are critical for performance, which is why programs with good locality (fewer distinct pages touched) run faster.

Q26. What is a page fault?

A page fault happens when a process accesses a page that's marked valid in its virtual space but is not currently loaded into physical RAM (it's on disk, in swap). The OS then: pauses the process → finds a free frame (or evicts one using a replacement policy like LRU) → loads the page from disk → updates the page table → resumes the process. It's expensive (disk I/O), so minimizing page faults matters for performance.

I/O & Interrupts

Q27. What is an interrupt, and how is it different from polling?

Polling: CPU repeatedly checks a device's status register in a loop, wasting cycles even when the device has nothing to report.

Interrupt-driven I/O: the device signals the CPU only when it actually needs attention (e.g. data ready). The CPU:

  • 1. Finishes current instruction
  • 2. Saves current state (PC, registers) onto the stack
  • 3. Jumps to the Interrupt Service Routine (ISR) via the interrupt vector table
  • 4. Executes the ISR
  • 5. Restores state and resumes the interrupted program

Interrupts are more efficient because the CPU is free to do other work between events.

Fig 7 — Interrupt handling flow: the CPU parks the current program, services the ISR, and returns

Q28. What is bus arbitration, and why is it needed?

Only one device can drive the shared bus at a time. When multiple devices (CPU, DMA controller, peripherals) want to use the bus simultaneously, an arbiter decides who gets access, using a scheme such as:

  • Daisy chaining — a priority signal passes serially device to device; simple but slower and fixed-priority.
  • Centralized (polling/priority encoder) — a central arbiter grants the bus based on priority or request lines.
  • Distributed arbitration — devices negotiate among themselves without a central controller (used in some modern buses).

Without arbitration, two devices driving the bus at once would corrupt data — this is the hardware equivalent of a race condition.

Q29. What is DMA (Direct Memory Access) and why is it useful?

Normally, moving data between an I/O device and memory requires the CPU to copy it word-by-word — wasteful for large transfers (disk reads, network packets). A DMA controller takes over the bus and moves data directly between the device and memory without CPU involvement, only interrupting the CPU once when the whole transfer is complete. This frees the CPU to do useful work in parallel with I/O transfers.

Multicore & Parallelism

Q30. Multicore vs multiprocessor — aren't they the same thing?

Close, but interviewers do check this distinction:

  • Multicore — multiple CPU cores on a single chip, typically sharing L3 cache and the memory controller.
  • Multiprocessor — multiple separate CPU chips on the same motherboard/system, each potentially with their own full cache hierarchy, communicating over a system interconnect.

Both fall under MIMD in Flynn's taxonomy. A modern server can be a multiprocessor system where each processor is itself multicore.

Q31. State Amdahl's Law and solve a quick example.

Amdahl's Law caps the speedup you can get from parallelizing part of a program:

Speedup = 1 / ( (1 - P) + P/N )

P = parallelizable fraction of the program
N = number of processors

Example: 80% of a program can be parallelized (P = 0.8), running on 4 cores (N = 4).

Speedup = 1 / ( (1 - 0.8) + 0.8/4 )
        = 1 / ( 0.2 + 0.2 )
        = 1 / 0.4
        = 2.5x

Key insight interviewers want to hear: "Even with infinite cores, speedup can never exceed 1/(1-P) — here that ceiling is 1/0.2 = 5x. The serial portion always dominates eventually."

Fig 8 — Speedup curve flattens out — the serial fraction sets a hard ceiling

Q32. What is the difference between parallelism and concurrency, from a hardware standpoint?

Concurrency is about structuring a program as multiple independent tasks that can be interleaved — it can happen even on a single core via time-slicing/context switching, and doesn't require multiple physical execution units. Parallelism requires actual simultaneous execution on multiple hardware units (multiple cores, multiple ALUs). One-liner: "Concurrency is about dealing with lots of things at once; parallelism is about doing lots of things at once." — every parallel system is concurrent, but not every concurrent system is parallel.

Rapid-Fire Round

Skim this right before you walk in — these are the one-liners interviewers use as warm-up or filler questions.

What is a bus?
A shared communication pathway (address, data, control lines) connecting CPU, memory, and I/O.
Multiprogramming vs multiprocessing?
Multiprogramming = multiple programs share one CPU via context switching. Multiprocessing = multiple CPUs execute truly in parallel.
What is a context switch?
Saving the state of a running process and loading another's, so the CPU can switch between processes.
What is thrashing?
Excessive page faulting where the system spends more time swapping pages than executing — usually from over-committing memory.
What is a superscalar processor?
A CPU that can issue and execute more than one instruction per clock cycle using multiple execution units.
What is out-of-order execution?
CPU executes instructions as their operands become ready, rather than strictly in program order, then retires results in order.
What is Amdahl's Law used for?
Estimating the max theoretical speedup from parallelizing part of a task — speedup is limited by the serial portion.
What is a cache hit ratio?
Fraction of memory accesses found in cache: Hits / (Hits + Misses).
What's the difference between microarchitecture and ISA?
ISA is the instruction set contract (e.g. x86-64); microarchitecture is the specific chip implementation of it (e.g. Zen 4, Golden Cove).
What is pipelining's theoretical speedup formula?
Speedup ≈ number of pipeline stages, assuming no stalls/hazards and a filled pipeline.
Interview tip: Infosys technical rounds often mix 2-3 conceptual questions with one quick numerical (AMAT, hit ratio, or speedup calculation). Practice the AMAT example in Q15 until you can redo it without hesitation.
