01

Foundations & Chomsky Hierarchy

The vocabulary everything else in TOC is built on — alphabets, languages, and the four-level hierarchy interviewers use to organize every follow-up question.

Q. What is a language, formally, in TOC?

A language is simply a set of strings over some alphabet Σ. If Σ = {0,1}, then any subset of Σ* (all possible strings, including the empty string) is a language — for example "all binary strings with an even number of 1s."

Q. Explain the Chomsky hierarchy.

It's four nested classes of languages, each recognized by a specific machine and generated by a specific grammar type:

  • Type 3 — Regular: recognized by Finite Automata, generated by regular grammars.
  • Type 2 — Context-Free: recognized by Pushdown Automata (PDA), generated by CFGs.
  • Type 1 — Context-Sensitive: recognized by Linear Bounded Automata (LBA).
  • Type 0 — Recursively Enumerable: recognized by Turing Machines.

Each class is a strict superset of the one before it: Regular ⊂ Context-Free ⊂ Context-Sensitive ⊂ Recursively Enumerable.

Each level fully contains the next — Regular ⊂ Context-Free ⊂ Context-Sensitive ⊂ Recursively Enumerable.
Q. Where do recursive languages fit relative to recursively enumerable ones?

Recursive languages (decidable by some TM that always halts) sit strictly between Context-Sensitive and Recursively Enumerable. Every recursive language is recursively enumerable, but not every recursively enumerable language is recursive — the Halting Problem's language is the standard example of the latter.

Q. What's the difference between a grammar and an automaton?

A grammar generates strings of a language using production rules (a top-down, constructive view). An automaton recognizes/accepts strings by processing them (a bottom-up, computational view). Both describe the same language classes — that equivalence is a core theme of TOC.

Q. What is Kleene closure (Σ*) vs positive closure (Σ⁺)?

Σ* is the set of all strings over Σ including the empty string ε. Σ⁺ is the same but excludes ε. So Σ* = Σ⁺ ∪ {ε}.

02

Finite Automata

DFA vs NFA, why they're equally powerful, and how to shrink one down — this is the section interviewers use to check you actually understand automata, not just memorized definitions.

Q. What is a DFA? Give its formal definition.

A Deterministic Finite Automaton is a 5-tuple (Q, Σ, δ, q0, F): a finite set of states Q, an input alphabet Σ, a transition function δ: Q × Σ → Q (exactly one next state per symbol), a start state q0, and a set of accepting states F. For every state and every input symbol, there is exactly one defined transition.

DFA accepting strings ending in "01" — double circle (q2) marks the accepting state, the incoming arrow marks the start state (q0).
Q. How does an NFA differ from a DFA?

An NFA allows zero, one, or multiple transitions on the same symbol from a given state, and also permits ε-transitions (moving states without consuming input). Its transition function is δ: Q × (Σ ∪ {ε}) → 2^Q — it maps to a set of possible next states rather than one.

Q. If NFAs are "non-deterministic," why are they equally powerful as DFAs?

Because of the subset construction: any NFA with n states can be converted to an equivalent DFA whose states are subsets of the NFA's states (at most 2^n states). Non-determinism only affects the construction's convenience and size, not what languages can be recognized — both accept exactly the regular languages.

Q. What is an ε-NFA and why is it useful?

An NFA that additionally allows transitions on the empty string ε without consuming input. It's mainly a convenience for building automata compositionally (e.g. constructing an NFA from a regular expression via Thompson's construction) — it's then converted away using ε-closure before subset construction.

Q. How do you minimize a DFA?

The standard method is table-filling / partition refinement:

  • Remove unreachable states from the start state.
  • Start by partitioning states into two groups: accepting and non-accepting.
  • Repeatedly split groups where two states in the same group go to different groups on some input symbol.
  • Stop when no group can be split further — each remaining group merges into a single state.
Q. What is the Myhill-Nerode theorem, in plain terms?

Two strings x and y are "equivalent" for a language L if, for every suffix z, either both xz and yz are in L or neither is. The theorem says L is regular if and only if this equivalence relation has finitely many classes — and that number equals the minimum number of states in a DFA for L. It's the theoretical justification behind DFA minimization.

Q. Can every NFA be converted to a regular expression?

Yes — via the state elimination method. States are removed one at a time, and each removal is compensated for by labeling the remaining transitions with regular expressions that capture the paths through the eliminated state, until only the start and final state remain, connected by a single expression.

Q. How do you build a DFA that recognizes the intersection or union of two regular languages?

Using the product construction: build a new DFA whose states are pairs (p, q) — one state from each original DFA. The new machine tracks both machines running in parallel on the same input. For intersection, a pair state is accepting only if both p and q are accepting; for union, if either is accepting.

Q. What is a "dead state" / "trap state" in a DFA, and why is it needed?

A DFA's transition function must be total — defined for every state and every input symbol. A trap state is a non-accepting state with self-loops on every symbol, used to absorb any input that should never lead to acceptance (e.g. an invalid symbol appearing early in a pattern). It keeps the DFA formally complete without changing the language it accepts.

Q. What is the difference between a Moore machine and a Mealy machine?

Both are finite automata with output, but a Moore machine's output depends only on the current state, while a Mealy machine's output depends on the current state and the current input symbol. Mealy machines often need fewer states for the same task, but Moore machines are simpler to reason about since output changes only on state transitions.

03

Regular Expressions & Languages

This is where interviewers test whether you can actually prove a language is or isn't regular — pumping lemma questions show up constantly.

Q. State the Pumping Lemma for regular languages.

If L is regular, there exists a pumping length p such that any string s ∈ L with |s| ≥ p can be split into three parts s = xyz where:

  • |y| > 0 (the pumped part is non-empty)
  • |xy| ≤ p (pumping happens within the first p characters)
  • xyⁱz ∈ L for every i ≥ 0 (repeating y any number of times keeps the string in L)
Q. Use the pumping lemma to show L = {0ⁿ1ⁿ | n ≥ 0} is not regular.

Assume L is regular with pumping length p. Pick s = 0ᵖ1ᵖ. Since |xy| ≤ p, y must consist only of 0s. Pumping (i=2) increases the number of 0s but not 1s, producing a string not of the form 0ⁿ1ⁿ — a contradiction. So L is not regular. This is the textbook template interviewers expect almost verbatim.

Q. Are regular languages closed under union, intersection, and complement?

Yes to all three — regular languages are closed under union, intersection, complement, concatenation, and Kleene star. This is usually shown constructively: e.g. complement by swapping accept/non-accept states in a DFA, intersection via the product construction of two DFAs.

Q. Is {ww | w ∈ {0,1}*} regular?

No. Intuitively a finite-state machine can't "remember" an arbitrarily long first half of the string to compare it against the second half — a pumping lemma argument on a string like 0ᵖ10ᵖ1 confirms this formally.

Q. What's the difference between a regular expression and a regular grammar?

Both describe exactly the regular languages, but a regular expression is a compact algebraic notation (using union, concatenation, and star), while a regular grammar is a set of production rules restricted to a left-linear or right-linear form (e.g. A → aB or A → a).

Thompson's construction sketch for (a|b)c* — union of a/b feeds into a state, then c loops via an ε-edge before reaching the final state f.
Q. What is Arden's theorem and where is it used?

For an equation of the form R = QR + P (with ε ∉ Q), Arden's theorem gives the unique solution R = QR as R = Q*P. It's used to convert a finite automaton directly into a regular expression by writing one equation per state (in terms of its incoming transitions) and solving the system.

Q. Is the language L = {aⁿ | n is prime} regular?

No. Applying the pumping lemma: pick a prime p ≥ pumping length, take s = a^p; pumping down or up changes the exponent to a value that can always be shown composite for suitable choice of i, contradicting the requirement that all pumped strings stay in L.

04

Context-Free Grammars & PDA

CFGs model nested structure (brackets, expressions, code blocks) that finite automata simply cannot track — that's the recurring "why do we need this" answer.

Q. What is a Context-Free Grammar (CFG)?

A 4-tuple (V, Σ, R, S): a set of non-terminals V, terminals Σ, production rules R of the form A → α (a single non-terminal on the left, any string of terminals/non-terminals on the right), and a start symbol S. The "context-free" part means the left side is always a single non-terminal — no surrounding context is checked before applying a rule.

Q. What is ambiguity in a CFG, and why does it matter?

A grammar is ambiguous if some string in its language has two or more distinct parse trees (or leftmost derivations). It matters because compilers and parsers need a single, unambiguous interpretation — the classic example is the dangling-else problem or E → E+E | E*E | id not encoding operator precedence.

One parse tree for id + id + id under E → E+E | id — the other valid grouping (right-associative) is what makes this grammar ambiguous.
Q. What is Chomsky Normal Form (CNF)?

A CFG is in CNF if every production is one of two forms: A → BC (two non-terminals) or A → a (a single terminal), with an optional S → ε for the start symbol. Every CFG can be converted to an equivalent one in CNF, and CNF is what makes the CYK parsing algorithm work in O(n³) time.

Q. What is a Pushdown Automaton (PDA), and how does it extend a finite automaton?

A PDA is an NFA equipped with an auxiliary stack of unbounded size. Transitions can read/pop the top of the stack and push new symbols. This stack is exactly what lets a PDA count and match nested structures (like balanced parentheses), which a finite automaton's fixed, finite memory cannot do.

Q. Are CFGs and PDAs equivalent in power?

Yes — a language is context-free if and only if some PDA accepts it. The proof is constructive in both directions: any CFG can be converted to an equivalent PDA (simulating derivations using the stack), and any PDA can be converted back to an equivalent CFG.

Q. State the Pumping Lemma for context-free languages.

For a CFL L, there's a pumping length p such that any string s ∈ L with |s| ≥ p can be split into five parts s = uvxyz where |vy| > 0, |vxy| ≤ p, and uvⁱxyⁱz ∈ L for all i ≥ 0. It's used the same way as the regular-language version — to prove languages like {aⁿbⁿcⁿ} are not context-free.

Q. Is a Deterministic PDA (DPDA) as powerful as a (non-deterministic) PDA?

No. DPDAs recognize a strict subset of context-free languages, called deterministic context-free languages. A classic example only a non-deterministic PDA handles is the language of even-length palindromes — the machine can't know when it has reached the middle of the string without guessing.

PDA sketch for 0ⁿ1ⁿ: push a marker for every 0 read in q0, then pop one for every 1 read in q1 — accept only if the stack empties exactly (hits Z) when input ends.
Q. What are the two common PDA acceptance modes?

Acceptance by final state: the PDA accepts if it's in an accepting state after reading all input, regardless of stack contents. Acceptance by empty stack: the PDA accepts if the stack is empty after reading all input, regardless of state. Both modes define the same class — context-free languages — and either can be converted to the other.

Q. What is the CYK algorithm used for?

It's a dynamic-programming membership-testing algorithm: given a CFG in Chomsky Normal Form and a string of length n, CYK decides whether the string belongs to the grammar's language in O(n³) time by filling a triangular table of which non-terminals can generate each substring.

05

Turing Machines

The model of "what a computer can do, period." Expect at least one conceptual question here about why TMs are the ceiling of computability.

Q. What is a Turing Machine (TM), formally?

A 7-tuple (Q, Σ, Γ, δ, q0, qaccept, qreject) featuring an infinite tape, a read/write head, states Q, an input alphabet Σ, a tape alphabet Γ (which includes a blank symbol), and a transition function δ: Q × Γ → Q × Γ × {L, R} that reads a symbol, writes a symbol, changes state, and moves the head left or right.

The tape is infinite in both directions; the head reads/writes the cell under it, then moves L or R based on δ(state, symbol).
Q. Why is a Turing Machine more powerful than a PDA?

A PDA's stack only allows last-in-first-out access, while a TM's tape gives unrestricted, unlimited random-access read/write memory in both directions. This lets a TM simulate any algorithm — including things a stack can't do, like comparing two arbitrary-length substrings anywhere in the input.

Q. What is the Church-Turing thesis?

An (unprovable, but universally accepted) claim that any function "computable" by an intuitive algorithmic process can be computed by a Turing Machine. It's why TMs are used as the formal definition of "computable" and "algorithm" in computer science.

Q. What is a Universal Turing Machine (UTM)?

A single TM that takes as input the description (encoding) of any other TM M along with an input w, and simulates M running on w. It's the theoretical ancestor of the stored-program computer — one machine that can run any program.

Q. Do non-deterministic Turing Machines recognize more languages than deterministic ones?

No. Every non-deterministic TM has an equivalent deterministic TM (which can simulate all branches, e.g. via breadth-first search over the computation tree). They differ in efficiency, not in the class of languages they can recognize.

Q. What's the difference between a language being "recognized" and "decided" by a TM?

A TM recognizes (accepts) a language if it halts and accepts every string in the language — but it may loop forever on strings not in the language. A TM decides a language if it always halts, accepting strings in the language and rejecting all others. "Decidable" languages are a strict subset of "recognizable" ones.

Q. What are common "variant" Turing Machines, and why do they matter?

Multi-tape TMs, multi-track TMs, and 2-way infinite tape TMs are all variants used to simplify design. The key interview point:

  • Every variant is equivalent in power to the standard single-tape TM.
  • A multi-tape TM can be simulated by a single-tape TM with at most a polynomial (quadratic) slowdown — it doesn't change what's computable, only efficiency.
Q. What is a Linear Bounded Automaton (LBA)?

A Turing Machine whose tape is restricted to exactly the length of the input (no extra working space beyond that). LBAs recognize precisely the context-sensitive languages — one level below unrestricted TMs in the Chomsky hierarchy.

06

Decidability & Undecidability

The Halting Problem is almost guaranteed to come up. Know the diagonalization proof idea, not just the statement.

Q. What is the Halting Problem, and why is it undecidable?

It asks: given a TM M and input w, does M halt on w? It's proven undecidable by contradiction using diagonalization:

  • Assume a TM H decides it, i.e. H(M, w) outputs "halts" or "loops."
  • Build a new machine D that runs H(M, M) and does the opposite: loops if H says "halts," halts if H says "loops."
  • Run D on itself: D(D) halts iff it doesn't halt — a contradiction, so H cannot exist.
Q. What's the difference between decidable, recognizable (semi-decidable), and non-recognizable languages?

Decidable: a TM always halts and correctly accepts/rejects. Recognizable: a TM halts and accepts on "yes" instances, but may loop forever on "no" instances. Non-recognizable: no TM even reliably accepts the "yes" instances — the complement of the Halting Problem is a standard example.

Q. What is a reduction, and how is it used to prove undecidability?

A reduction from problem A to problem B shows that if you could solve B, you could use that to solve A. So if A is already known to be undecidable, and A reduces to B, then B must be undecidable too (otherwise you'd have a way to decide A). Most undecidability proofs reduce from the Halting Problem.

Q. What does Rice's Theorem say?

Any non-trivial property of the language recognized by a Turing Machine (a property that's true for some TMs and false for others) is undecidable. In practice, this means questions like "does this program's language contain only even-length strings?" are undecidable in general — you can't algorithmically inspect semantic behavior of arbitrary programs.

Q. Is the Post Correspondence Problem (PCP) decidable?

No, PCP is undecidable. It's a common tool used to prove other problems undecidable (e.g. ambiguity of a CFG is undecidable, shown via reduction from PCP).

Nested strictly: Regular/CFL ⊂ Decidable ⊂ Recognizable. Undecidable-but-unrecognizable languages (like the Halting Problem's complement) sit entirely outside the outer circle.
Q. Is the complement of the Halting Problem recognizable?

No. The Halting Problem's language is recognizable but not decidable. A standard theorem says a language is decidable if and only if both it and its complement are recognizable. Since the Halting Problem isn't decidable, its complement cannot be recognizable — it's an example of a language that is neither recognizable nor co-recognizable.

Q. Give one concrete example each of a trivial and a non-trivial property (in the sense of Rice's Theorem).

Trivial (decidable, but useless): "Is the language recognized by TM M equal to itself?" — always true. Non-trivial (undecidable): "Is L(M) empty?", "Does L(M) contain the string 'abc'?", "Is L(M) regular?" — each is true for some TMs and false for others, so Rice's Theorem makes all of them undecidable.

07

Complexity: P, NP & Beyond

Sits right on the border between TOC and DSA/Algorithms — interviewers love this overlap because it's practical.

Q. Define the classes P and NP.

P is the set of decision problems solvable by a deterministic TM in polynomial time. NP is the set of decision problems for which a proposed solution ("certificate") can be verified in polynomial time by a deterministic TM — equivalently, solvable in polynomial time by a non-deterministic TM.

Q. What does NP-Complete mean, and how is it different from NP-Hard?

A problem is NP-Complete if it's in NP and every problem in NP can be reduced to it in polynomial time — making it one of the "hardest" problems in NP. A problem is NP-Hard if it has that second property (everything in NP reduces to it) but isn't required to be in NP itself — so NP-Hard problems can be harder than NP, or not even be decision problems (e.g. optimization versions of NP-Complete problems).

Q. What is the Cook-Levin theorem?

It proves that Boolean Satisfiability (SAT) is NP-Complete — the first problem ever shown to be NP-Complete. Every other NP-Completeness proof today works by reducing SAT (or another already-proven NP-Complete problem) to the new problem, rather than repeating Cook-Levin's original argument from scratch.

Q. Is P = NP? What's the current status?

It's the biggest open problem in computer science — unresolved. Most researchers believe P ≠ NP, but no proof exists either way. Practically: if P = NP were proven with a constructive algorithm, problems like factoring, scheduling, and many optimization tasks would become efficiently solvable, with massive implications for cryptography.

Q. Name a few classic NP-Complete problems.

SAT and 3-SAT, the Traveling Salesman decision problem, the Knapsack decision problem, Graph Coloring, the Clique problem, Vertex Cover, and the Hamiltonian Path/Cycle problem.

Q. What's the difference between NP and co-NP?

NP problems have "yes" instances that are efficiently verifiable. co-NP problems have "no" instances that are efficiently verifiable (co-NP is the class of complements of NP problems). Whether NP = co-NP is also open — for example, it's easy to verify a graph is 3-colorable given a coloring, but not obviously easy to verify it isn't.

NP-Complete = the overlap of NP and NP-Hard. If P = NP were proven, the P and NP ellipses would collapse into one — SAT and every NP-Complete problem would become polynomial-time solvable.
Q. What is a polynomial-time reduction, and how is it used to prove NP-Completeness?

A problem A reduces to B (written A ≤p B) if any instance of A can be transformed into an instance of B in polynomial time, such that the answers match. To prove a new problem X is NP-Complete: (1) show X ∈ NP by giving a polynomial-time verifier, and (2) reduce a known NP-Complete problem to X — proving X is at least as hard as everything already known to be NP-Complete.

Q. What is the difference between time complexity and space complexity classes, e.g. PSPACE?

Time complexity classes (like P, NP) bound the number of computation steps. Space complexity classes (like PSPACE, the set of problems solvable using polynomial memory regardless of time) bound memory used. It's known that P ⊆ NP ⊆ PSPACE, and PSPACE problems can require exponential time even though they use only polynomial space.
