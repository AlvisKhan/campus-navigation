01

OS Basics

Warm-up questions. Interviewers use these to gauge whether you understand fundamentals before going deeper.

easy What is an Operating System, in your own words?+

It's the system software that sits between the hardware and the applications. It manages the CPU, memory, storage, and I/O devices, and gives programs a consistent way to use them through system calls.

One-liner to lead with: "An OS is a resource manager and an abstraction layer — it hides hardware complexity from applications and users."
easy What are the main functions of an OS?+
  • Process management — creating, scheduling, terminating processes
  • Memory management — allocation, paging, virtual memory
  • File management — organizing, storing, retrieving files
  • I/O / device management — talking to hardware via drivers
  • Security & protection — access control between users/processes
mid Differentiate multiprogramming, multitasking, and multiprocessing.+
TermMeaning
MultiprogrammingMultiple programs kept in memory so the CPU always has something to run when one is waiting on I/O
MultitaskingMultiple tasks appear to run simultaneously on a single CPU via fast time-sharing
MultiprocessingMultiple CPUs actually execute processes in parallel, truly simultaneously
easy Name the types of Operating Systems.+

Batch OS, Time-sharing OS, Distributed OS, Network OS, Real-Time OS (RTOS — hard/soft real-time), and Multiprocessing OS. If asked for an example of RTOS, mention embedded systems like pacemakers or flight control software.

02

Process Management

This is asked in almost every OS round. Know process states and PCB by heart.

easy What's the difference between a process, a program, and a thread?+

Program is passive — just code sitting on disk. Process is that program loaded into memory and being executed — it has its own address space, PCB, and resources. Thread is the smallest unit of execution within a process — multiple threads of the same process share code and data but have their own stack, registers, and program counter.

mid Explain the process states with a diagram in words.+

New → Ready → Running → Waiting/Blocked → Terminated

  • New: process being created
  • Ready: waiting to be assigned the CPU
  • Running: instructions being executed
  • Waiting: blocked on I/O or an event
  • Terminated: finished execution

A running process can go back to Ready (preempted) or to Waiting (needs I/O), and from Waiting it returns to Ready once the event completes — never straight back to Running.

mid What information does a PCB (Process Control Block) hold?+

Process ID, process state, program counter, CPU registers, CPU scheduling info (priority), memory management info (base/limit registers, page tables), accounting info, and I/O status (open file list, allocated devices). It's created at process creation and destroyed at termination.

mid What is a context switch, and why is it "pure overhead"?+

It's the act of saving the CPU state (registers, PC) of the currently running process into its PCB, then loading the saved state of the next process to run. It's called overhead because the CPU does zero useful computation during the switch itself — the time spent switching is time not spent running any process.

hard Why are threads called "lightweight" compared to processes?+

Creating a process means allocating a fresh address space, file descriptors, and other OS resources — expensive. Threads within the same process share all of that (code, data, heap, open files); only the stack, registers, and program counter are separate per thread. So creating/switching threads costs far less than creating/switching processes.

hard What are zombie and orphan processes?+

Zombie: a process that has finished executing but its entry still exists in the process table because the parent hasn't yet called wait() to read its exit status.

Orphan: a process whose parent terminated before it did — it gets adopted by the init (or root) process, which then reaps it on completion.

03

CPU Scheduling

Know all algorithm names, and be ready to solve a small Gantt-chart numerical if asked.

easy Why does an OS need CPU scheduling at all?+

To maximize CPU utilization and throughput while keeping response/waiting time low, by deciding which ready process gets the CPU next whenever it's free.

mid List the main CPU scheduling algorithms and one line on each.+
AlgorithmIdeaCatch
FCFSFirst come, first servedConvoy effect — short jobs stuck behind long ones
SJFShortest job runs firstOptimal avg wait time, but can starve long jobs
PriorityHighest priority runs firstStarvation risk — fixed by aging
Round RobinFixed time quantum, cyclic orderFair, ideal for time-sharing; quantum size is critical
Multilevel QueueSeparate queues per process type (fg/bg)Used in real OS schedulers
mid What's the difference between preemptive and non-preemptive scheduling?+

Preemptive: the OS can forcibly take the CPU away from a running process (e.g. Round Robin, Priority with preemption). Non-preemptive: once a process gets the CPU, it keeps it until it finishes or voluntarily blocks (e.g. FCFS, non-preemptive SJF).

mid What is starvation, and how does aging fix it?+

Starvation: a low-priority process waits indefinitely because higher-priority processes keep arriving and jumping ahead of it. Aging: the fix — gradually increase the priority of a process the longer it waits, so it's eventually guaranteed to run.

hard Quick numerical: 3 processes with burst times 6, 8, 7 arrive together. Find average waiting time using SJF.+

Order by shortest burst first: P1(6) → P3(7) → P2(8).

  • P1 waits 0
  • P3 waits 6
  • P2 waits 6+7 = 13

Average waiting time = (0 + 6 + 13) / 3 = 6.33

Practice 2-3 of these — Infosys often gives a tiny Gantt chart numerical as a written or verbal problem.
04

Process Synchronization

This is where code questions show up. Know semaphore syntax and the producer-consumer pattern cold.

mid What is a race condition?+

A situation where two or more processes/threads access shared data concurrently, and the final result depends on the unpredictable order/timing of execution — leading to inconsistent or wrong output.

mid What are the 3 requirements of a solution to the critical section problem?+
  1. Mutual Exclusion — only one process in the critical section at a time
  2. Progress — if no process is in the CS, one of the waiting ones must be allowed in without indefinite delay
  3. Bounded Waiting — there's a limit on how many times other processes can enter before a waiting process gets its turn
mid What's the difference between a mutex and a semaphore?+
MutexSemaphore
Binary locking mechanism (locked/unlocked)Can be binary or counting (integer value)
Owned by the thread that locked itNo concept of ownership
Purely for mutual exclusionCan also be used for signaling between threads, or controlling access to N resources
hard Write the wait() and signal() semaphore operations and explain them.+

wait() (also called P) decrements the semaphore; if it goes negative, the process blocks. signal() (also called V) increments the semaphore and wakes a waiting process if any.

pseudocode
wait(Semaphore S) {
    while (S <= 0)
        ; // busy wait / block process
    S = S - 1;
}

signal(Semaphore S) {
    S = S + 1;
}
hard Code: Solve the Producer-Consumer problem using semaphores (C-style pseudocode).+

Classic pattern: empty counts free slots, full counts filled slots, mutex protects the buffer itself.

c
semaphore mutex = 1;   // binary: protects buffer
semaphore empty = N;   // counts empty slots
semaphore full  = 0;   // counts filled slots

producer() {
    while (true) {
        item = produce_item();
        wait(empty);      // wait for a free slot
        wait(mutex);      // lock buffer
        insert_item(item);
        signal(mutex);    // unlock buffer
        signal(full);     // one more filled slot
    }
}

consumer() {
    while (true) {
        wait(full);       // wait for a filled slot
        wait(mutex);      // lock buffer
        item = remove_item();
        signal(mutex);    // unlock buffer
        signal(empty);    // one more empty slot
        consume_item(item);
    }
}
Interview tip: If asked "why two semaphores plus a mutex," explain: empty/full handle capacity synchronization, mutex handles mutual exclusion on the buffer itself — mixing the two up is the #1 mistake candidates make.
hard Code: Readers-Writers problem — readers preference version.+

Multiple readers can read simultaneously; a writer needs exclusive access.

c
int read_count = 0;
semaphore mutex = 1;    // protects read_count
semaphore wrt   = 1;    // exclusive access for writer

writer() {
    wait(wrt);
    write_to_resource();
    signal(wrt);
}

reader() {
    wait(mutex);
    read_count++;
    if (read_count == 1)
        wait(wrt);     // first reader locks out writers
    signal(mutex);

    read_the_resource();

    wait(mutex);
    read_count--;
    if (read_count == 0)
        signal(wrt);   // last reader lets writers in
    signal(mutex);
}
mid What is the Dining Philosophers problem used to illustrate?+

Five philosophers sit around a table with one fork between each pair — need two forks to eat. If every philosopher picks up their left fork at once, all wait forever for the right fork: a live illustration of deadlock (and, with bad fixes, starvation). Common solution: allow at most 4 philosophers to try picking up forks simultaneously, or impose an ordering (pick up lower-numbered fork first).

05

Deadlocks

Know the 4 conditions by name — this is asked almost every single time.

mid What are the 4 necessary conditions for deadlock (Coffman conditions)?+
  1. Mutual Exclusion — at least one resource held in a non-shareable mode
  2. Hold and Wait — a process holds one resource while waiting for another
  3. No Preemption — a resource can't be forcibly taken away
  4. Circular Wait — a closed chain of processes, each waiting for a resource held by the next
All 4 must hold simultaneously for deadlock — breaking even one prevents it. This is the basis of every prevention technique.
mid How do you handle deadlocks in an OS — name the strategies.+
  • Prevention — design the system so one of the 4 conditions can never hold
  • Avoidance — allow requests only if the resulting state is "safe" (Banker's Algorithm)
  • Detection & Recovery — let deadlocks happen, detect via resource-allocation graph, then kill/preempt a process
  • Ignore it (Ostrich algorithm) — what most general-purpose OS like Linux/Windows actually do, since deadlocks are rare in practice
hard Explain the Banker's Algorithm in simple terms.+

It's a deadlock-avoidance algorithm. Before granting a resource request, the OS pretends to grant it and checks: "if I do this, is there still some order in which every process can finish with the resources available?" If yes, the state is safe and the request is granted; if no, the process must wait. It needs to know the maximum resources each process might ever request in advance.

mid Real-world tip: how would you avoid deadlock in your own code (e.g. with multiple locks)?+

Good practical answer: always acquire multiple locks in a fixed global order, use lock timeouts, avoid nested locking where possible, and prefer higher-level concurrency primitives over raw locks. This is a common follow-up after the theory question — mention it even if not asked.

06

Memory Management

Paging vs segmentation and virtual memory come up constantly — know the trade-offs, not just definitions.

easy What's the difference between logical and physical addresses?+

Logical (virtual) address — generated by the CPU during program execution. Physical address — the actual location in RAM. The MMU (Memory Management Unit) translates logical to physical at runtime.

mid Explain paging vs segmentation.+
PagingSegmentation
Fixed-size blocks (pages/frames)Variable-size logical blocks (code, stack, heap)
No external fragmentationExternal fragmentation possible
Internal fragmentation possibleNo internal fragmentation
Invisible to the programmerMatches how a programmer thinks about a program
mid What is virtual memory and why do we need it?+

A technique that lets a process execute even if it isn't fully loaded in physical memory — it uses disk space (the swap area) to simulate extra RAM, bringing pages in on demand. This lets programs larger than physical RAM run, and lets multiple programs share memory safely and efficiently.

mid What is a page fault?+

It occurs when a process accesses a page that isn't currently in physical memory. The OS traps this, fetches the required page from disk into a free frame, updates the page table, and resumes the process.

hard Name the page replacement algorithms and explain Belady's Anomaly.+
  • FIFO — replace the oldest loaded page
  • LRU — replace the page unused for the longest time
  • Optimal — replace the page that won't be needed for the longest time in the future (theoretical benchmark, not implementable in practice)
Belady's Anomaly: with FIFO, increasing the number of available frames can, counter-intuitively, increase the number of page faults instead of decreasing them.
mid What is thrashing, and how do you fix it?+

Thrashing is when the system spends more time swapping pages in and out than actually executing processes — usually caused by too many processes competing for too little physical memory (over-multiprogramming). Fix: reduce the degree of multiprogramming, or use the working-set model to allocate enough frames per process.

easy Internal vs external fragmentation — and how do you fix external fragmentation?+

Internal: allocated memory block is slightly bigger than requested — wasted space is trapped inside the block. External: total free memory is enough, but it's scattered in small non-contiguous chunks, so a large request can't be satisfied. Fixed via compaction — shifting memory contents to merge free space into one large block.

File Systems & I/O

Lower frequency than sections 2-6, but still shows up — know the allocation methods and disk scheduling names.

mid What are the file allocation methods on disk?+
MethodTrade-off
ContiguousFast sequential/random access, but suffers external fragmentation and fixed growth limits
LinkedNo external fragmentation, but slow random access (must traverse the chain)
IndexedGood random access via an index block of pointers, but extra storage for the index itself
mid Name the disk scheduling algorithms.+

FCFS, SSTF (Shortest Seek Time First), SCAN (elevator algorithm — sweeps end to end), C-SCAN (circular SCAN), LOOK and C-LOOK (like SCAN but only goes as far as the last request, not the disk end). All aim to minimize total seek time/head movement.

easy What is spooling?+

Simultaneous Peripheral Operations On-Line — output meant for a slow device (like a printer) is buffered on disk first, so the CPU isn't blocked waiting for the slow device and can move on to other work.

Common "Differentiate Between" Questions

Infosys interviewers love this format. Answer with 2-3 crisp points, not paragraphs.

mid Kernel mode vs User mode?+

Kernel mode: unrestricted access to hardware, can execute privileged instructions. User mode: restricted — applications run here and must request OS services via system calls to do anything privileged (like file I/O).

mid What is a system call? Give examples.+

The programmatic interface through which a user program requests a service from the OS kernel. Examples: fork() (create process), exec() (run a program), read()/write() (I/O), wait() (wait for child).

hard Monolithic kernel vs Microkernel?+

Monolithic: all OS services (file system, drivers, scheduler) run in kernel space — fast because there's no context switch between services, but less modular (e.g. Linux). Microkernel: only the bare minimum (IPC, basic scheduling, memory) runs in kernel space; everything else runs in user space as separate services — more modular and secure, but more IPC overhead (e.g. MINIX, QNX).

easy Swapping vs Paging?+

Swapping moves an entire process between RAM and disk. Paging moves individual fixed-size pages of a process — much more granular and efficient.
