01

Number of Islands

LeetCode 200
Medium

Given an m x n grid of '1' (land) and '0' (water), return the number of islands. An island is formed by connecting adjacent lands horizontally or vertically.

Intuition

Every unvisited '1' is the seed of a brand-new island. Once you find one, "erase" the whole landmass connected to it (DFS or BFS) so you never count it twice. The answer is just how many times you had to start a fresh erase.

Approach
  1. Scan every cell of the grid in order.
  2. When you hit a '1' that hasn't been visited, increment the island count.
  3. From that cell, run DFS/BFS marking every connected '1' as visited (or flip to '0').
  4. Continue scanning — visited land is skipped instantly.
Complexity
Time O(R·C)Space O(R·C) (recursion stack, worst case all land)
C++
class Solution {
public:
    void dfs(vector<vector<char>>& g, int r, int c) {
        if (r < 0 || c < 0 || r >= g.size() || c >= g[0].size() || g[r][c] != '1')
            return;
        g[r][c] = '0'; // mark visited in-place
        dfs(g, r+1, c); dfs(g, r-1, c);
        dfs(g, r, c+1); dfs(g, r, c-1);
    }
    int numIslands(vector<vector<char>>& grid) {
        int count = 0;
        for (int r = 0; r < grid.size(); r++)
            for (int c = 0; c < grid[0].size(); c++)
                if (grid[r][c] == '1') { count++; dfs(grid, r, c); }
        return count;
    }
};

Max Area of Island

LeetCode 695
Medium

Same grid setup as Number of Islands, but instead of counting islands, return the area of the largest one.

Intuition

Identical scanning skeleton to Number of Islands — the only change is that the DFS now needs to return a value (the size of the island it just explored) instead of just marking cells.

Approach
  1. Scan every cell; on an unvisited land cell, launch DFS.
  2. DFS returns 1 + sum of the four recursive calls, marking cells visited as it goes.
  3. Track the maximum value returned across all launches.
Complexity
Time O(R·C)Space O(R·C) worst case
C++
class Solution {
public:
    int dfs(vector<vector<int>>& g, int r, int c) {
        if (r<0||c<0||r>=g.size()||c>=g[0].size()||g[r][c]==0) return 0;
        g[r][c] = 0;
        return 1 + dfs(g,r+1,c) + dfs(g,r-1,c) + dfs(g,r,c+1) + dfs(g,r,c-1);
    }
    int maxAreaOfIsland(vector<vector<int>>& grid) {
        int best = 0;
        for (int r = 0; r < grid.size(); r++)
            for (int c = 0; c < grid[0].size(); c++)
                if (grid[r][c] == 1) best = max(best, dfs(grid, r, c));
        return best;
    }
};

Clone Graph

LeetCode 133
Medium

Given a reference node of a connected undirected graph, return a deep copy (clone) of the graph.

Intuition

The trap is infinite recursion from cycles. The fix is a hashmap from original node → clone: before recursing into a neighbor, check if you've already started cloning it. This turns the graph traversal into one that "remembers" what it has seen.

Approach
  1. Maintain unordered_map<Node*, Node*> visited.
  2. DFS(node): if node is in the map, return its clone immediately.
  3. Otherwise create the clone, store it in the map first (before recursing — this breaks cycles), then recursively clone each neighbor and push it into the clone's neighbor list.
Complexity
Time O(V + E)Space O(V)
C++
class Solution {
public:
    unordered_map<Node*, Node*> visited;
    Node* cloneGraph(Node* node) {
        if (!node) return nullptr;
        if (visited.count(node)) return visited[node];
        Node* clone = new Node(node->val);
        visited[node] = clone; // store before recursing (handles cycles)
        for (Node* nei : node->neighbors)
            clone->neighbors.push_back(cloneGraph(nei));
        return clone;
    }
};

04

Rotting Oranges

LeetCode 994
Medium

Grid cells are 0 (empty), 1 (fresh orange), or 2 (rotten). Every minute, a rotten orange rots its 4-directional fresh neighbors. Return the minutes until no cell is fresh, or -1 if impossible.

Intuition

All rotten oranges spread at the same time, so treat them as a single BFS frontier that starts simultaneously from every rotten cell — not one BFS per orange. Each BFS "layer" processed is exactly one minute passing.

Approach
  1. Push every initially rotten cell into the queue, count fresh oranges.
  2. BFS layer by layer; each layer = one minute. Rot fresh neighbors, decrement fresh count, push them.
  3. Track minutes as the number of layers processed.
  4. After BFS, if fresh count > 0, return -1, else return minutes.
Complexity
Time O(R·C)Space O(R·C)
C++
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int rows = grid.size(), cols = grid[0].size(), fresh = 0, minutes = 0;
        queue<pair<int,int>> q;
        for (int r=0;r<rows;r++) for (int c=0;c<cols;c++) {
            if (grid[r][c]==2) q.push({r,c});
            if (grid[r][c]==1) fresh++;
        }
        int dr[] = {1,-1,0,0}, dc[] = {0,0,1,-1};
        while (!q.empty() && fresh > 0) {
            int sz = q.size();
            for (int i=0;i<sz;i++) {
                auto [r,c] = q.front(); q.pop();
                for (int d=0;d<4;d++) {
                    int nr=r+dr[d], nc=c+dc[d];
                    if (nr>=0&&nc>=0&&nr<rows&&nc<cols&&grid[nr][nc]==1) {
                        grid[nr][nc] = 2; fresh--; q.push({nr,nc});
                    }
                }
            }
            minutes++;
        }
        return fresh == 0 ? minutes : -1;
    }
};

01 Matrix

LeetCode 542
Medium

Given a binary matrix, return the distance of every cell to its nearest 0.

Intuition

Rather than running BFS from every 1 toward the nearest 0 (slow), flip the direction: start BFS simultaneously from every 0 and expand outward. The first time a 1-cell is reached, that layer number is its shortest distance.

Approach
  1. Push all cells with value 0 into the queue with distance 0; mark visited.
  2. BFS outward; each unvisited neighbor gets current distance + 1.
  3. Continue until the queue is empty — every cell now holds its answer.
Complexity
Time O(R·C)Space O(R·C)
C++
class Solution {
public:
    vector<vector<int>> updateMatrix(vector<vector<int>>& mat) {
        int rows = mat.size(), cols = mat[0].size();
        vector<vector<int>> dist(rows, vector<int>(cols, -1));
        queue<pair<int,int>> q;
        for (int r=0;r<rows;r++) for (int c=0;c<cols;c++)
            if (mat[r][c]==0) { dist[r][c]=0; q.push({r,c}); }
        int dr[]={1,-1,0,0}, dc[]={0,0,1,-1};
        while (!q.empty()) {
            auto [r,c] = q.front(); q.pop();
            for (int d=0;d<4;d++) {
                int nr=r+dr[d], nc=c+dc[d];
                if (nr>=0&&nc>=0&&nr<rows&&nc<cols&&dist[nr][nc]==-1) {
                    dist[nr][nc] = dist[r][c] + 1;
                    q.push({nr,nc});
                }
            }
        }
        return dist;
    }
};

Number of Provinces

LeetCode 547
Medium

Given an n×n adjacency matrix where isConnected[i][j] = 1 means city i and j are directly connected, return the number of provinces (connected components).

Intuition

This is just "count connected components", and Union–Find makes that a one-pass counting exercise: union every connected pair, then count how many distinct roots remain.

Approach
  1. Initialize parent[i] = i for all n cities.
  2. For every pair (i, j) with isConnected[i][j] == 1, union(i, j).
  3. Count how many indices are their own root (find(i) == i) — that's the province count.
Complexity
Time O(n² · α(n))Space O(n)
C++
class Solution {
public:
    vector<int> parent, rnk;
    int find(int x) { return parent[x]==x ? x : parent[x]=find(parent[x]); }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (rnk[a] < rnk[b]) swap(a,b);
        parent[b] = a;
        if (rnk[a] == rnk[b]) rnk[a]++;
    }
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        parent.resize(n); rnk.assign(n, 0);
        for (int i=0;i<n;i++) parent[i]=i;
        for (int i=0;i<n;i++)
            for (int j=i+1;j<n;j++)
                if (isConnected[i][j]) unite(i,j);
        int count = 0;
        for (int i=0;i<n;i++) if (find(i)==i) count++;
        return count;
    }
};

Redundant Connection

LeetCode 684
Medium

A tree with n nodes had one extra edge added, creating a cycle. Given the edge list, find the edge that can be removed to restore a tree. If multiple answers exist, return the last one in the input.

Intuition

A tree has no cycles. Process edges one at a time with Union–Find: if the two endpoints of an edge are already in the same set before you union them, that edge is the one closing a cycle — it's your answer.

Approach
  1. Initialize DSU over n+1 nodes.
  2. For each edge [u, v] in order: if find(u) == find(v), return this edge immediately.
  3. Otherwise union(u, v) and continue.
Complexity
Time O(n · α(n))Space O(n)
C++
class Solution {
public:
    vector<int> parent;
    int find(int x) { return parent[x]==x ? x : parent[x]=find(parent[x]); }
    vector<vector<int>> findRedundantConnection(vector<vector<int>>& edges) {
        int n = edges.size();
        parent.resize(n+1);
        for (int i=0;i<=n;i++) parent[i]=i;
        for (auto& e : edges) {
            int a = find(e[0]), b = find(e[1]);
            if (a == b) return e; // closes a cycle
            parent[a] = b;
        }
        return {};
    }
};

Accounts Merge

LeetCode 721
Medium

Each account is [name, email1, email2, ...]. Two accounts belong to the same person if they share at least one email. Merge accounts and return each person's sorted, deduplicated email list.

Intuition

Think of every email as a node. Emails inside the same account are automatically connected. Union them all, and any two accounts sharing an email fall into the same connected component — group emails by their root.

Approach
  1. Map each unique email to an integer id; map id → owner name.
  2. For each account, union its first email's id with every other email's id in that account.
  3. Group all email ids by find(id) into buckets.
  4. For each bucket, sort the emails and prepend the owner's name.
Complexity
Time O(N log N) (N = total emails, sorting dominates)Space O(N)
C++
class Solution {
public:
    vector<int> parent;
    int find(int x){ return parent[x]==x ? x : parent[x]=find(parent[x]); }
    void unite(int a,int b){ parent[find(a)] = find(b); }

    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        unordered_map<string, int> emailId;
        unordered_map<int, string> emailOwner;
        int id = 0;
        for (auto& acc : accounts) {
            for (int i=1;i<acc.size();i++) {
                if (!emailId.count(acc[i])) emailId[acc[i]] = id++;
                emailOwner[emailId[acc[i]]] = acc[0];
            }
        }
        parent.resize(id);
        for (int i=0;i<id;i++) parent[i]=i;
        for (auto& acc : accounts) {
            int first = emailId[acc[1]];
            for (int i=2;i<acc.size();i++) unite(first, emailId[acc[i]]);
        }
        unordered_map<int, set<string>> groups;
        for (auto& [email, eid] : emailId) groups[find(eid)].insert(email);
        vector<vector<string>> res;
        for (auto& [root, emails] : groups) {
            vector<string> entry = { emailOwner[root] };
            entry.insert(entry.end(), emails.begin(), emails.end());
            res.push_back(entry);
        }
        return res;
    }
};

Course Schedule

LeetCode 207
Medium

There are numCourses courses labeled 0..n-1. prerequisites[i] = [a, b] means you must take b before a. Return true if you can finish all courses.

Intuition

"Can I finish all courses" is exactly "does this dependency graph have a cycle". Kahn's algorithm answers this by repeatedly removing nodes with zero remaining dependencies — if you can remove all of them, there's no cycle.

Approach
  1. Build adjacency list and an indegree array from prerequisites.
  2. Push all nodes with indegree 0 into a queue.
  3. Pop a node, "complete" it, decrement indegree of its neighbors; push any that hit 0.
  4. If the number of completed nodes equals numCourses, return true — else a cycle exists.
Complexity
Time O(V + E)Space O(V + E)
C++
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prereq) {
        vector<vector<int>> adj(numCourses);
        vector<int> indeg(numCourses, 0);
        for (auto& p : prereq) { adj[p[1]].push_back(p[0]); indeg[p[0]]++; }
        queue<int> q;
        for (int i=0;i<numCourses;i++) if (indeg[i]==0) q.push(i);
        int seen = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop(); seen++;
            for (int v : adj[u]) if (--indeg[v]==0) q.push(v);
        }
        return seen == numCourses;
    }
};

Course Schedule II

LeetCode 210
Medium

Same setup as Course Schedule, but return a valid ordering of courses, or an empty array if impossible.

Intuition

Kahn's algorithm doesn't just detect a cycle — the exact order in which nodes get dequeued is a valid topological order. Reuse the same BFS, just record output as you go.

Approach
  1. Same indegree/BFS setup as Course Schedule.
  2. Every time a node is popped, append it to the result list.
  3. If result.size() == numCourses, return it; otherwise return an empty array (cycle detected).
Complexity
Time O(V + E)Space O(V + E)
C++
class Solution {
public:
    vector<int> findOrder(int numCourses, vector<vector<int>>& prereq) {
        vector<vector<int>> adj(numCourses);
        vector<int> indeg(numCourses, 0);
        for (auto& p : prereq) { adj[p[1]].push_back(p[0]); indeg[p[0]]++; }
        queue<int> q;
        for (int i=0;i<numCourses;i++) if (indeg[i]==0) q.push(i);
        vector<int> order;
        while (!q.empty()) {
            int u = q.front(); q.pop(); order.push_back(u);
            for (int v : adj[u]) if (--indeg[v]==0) q.push(v);
        }
        return order.size()==numCourses ? order : vector<int>{};
    }
};

Alien Dictionary

LeetCode 269 (Premium)
Hard

A list of words is sorted according to an unknown alien alphabet. Derive the order of letters, or report that it's invalid.

Intuition

The hard part isn't the topo sort — it's extracting the graph. Comparing each pair of adjacent words, the first differing letter tells you "this letter comes before that letter" — one edge per adjacent word pair, at most.

Approach
  1. Add every distinct letter in the input as a node.
  2. For each pair of adjacent words, find the first index where characters differ; add edge word1[i] → word2[i] and stop comparing that pair.
  3. Edge case: if word1 is longer than word2 but is a prefix of it (e.g. "abc" before "ab"), the order is invalid.
  4. Run topological sort (Kahn's) over the letter graph. If it doesn't cover all letters, return "".
Complexity
Time O(C) where C = total chars across all wordsSpace O(1) alphabet-bounded
C++
class Solution {
public:
    string alienOrder(vector<string>& words) {
        unordered_map<char, unordered_set<char>> adj;
        unordered_map<char, int> indeg;
        for (auto& w : words) for (char c : w) indeg[c] = 0;

        for (int i=0;i+1<words.size();i++) {
            string& a = words[i]; string& b = words[i+1];
            int len = min(a.size(), b.size());
            bool found = false;
            for (int j=0;j<len;j++) {
                if (a[j] != b[j]) {
                    if (!adj[a[j]].count(b[j])) { adj[a[j]].insert(b[j]); indeg[b[j]]++; }
                    found = true;
                    break;
                }
            }
            if (!found && a.size() > b.size()) return ""; // invalid prefix order
        }

        queue<char> q;
        for (auto& [c, d] : indeg) if (d==0) q.push(c);
        string res;
        while (!q.empty()) {
            char u = q.front(); q.pop(); res += u;
            for (char v : adj[u]) if (--indeg[v]==0) q.push(v);
        }
        return res.size()==indeg.size() ? res : "";
    }
};

Network Delay Time

LeetCode 743
Medium

A signal starts at node k and travels through a weighted directed graph. Return the time for the signal to reach every node, or -1 if some node is unreachable.

Intuition

This is the textbook definition of "single-source shortest path with non-negative weights" — exactly what Dijkstra was designed for. Always expand the closest unfinalized node next, and a min-heap keeps that cheap.

Approach
  1. Build a weighted adjacency list.
  2. Min-heap of (distance, node), starting with (0, k). dist[] initialized to infinity.
  3. Pop the smallest; if already finalized with a better distance, skip.
  4. Relax all neighbors: if dist[u] + weight < dist[v], update and push.
  5. Answer is the max value in dist[] (or -1 if any node stayed infinity).
Complexity
Time O(E log V)Space O(V + E)
C++
class Solution {
public:
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {
        vector<vector<pair<int,int>>> adj(n+1);
        for (auto& t : times) adj[t[0]].push_back({t[1], t[2]});

        vector<int> dist(n+1, INT_MAX);
        dist[k] = 0;
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
        pq.push({0, k});

        while (!pq.empty()) {
            auto [d, u] = pq.top(); pq.pop();
            if (d > dist[u]) continue;
            for (auto& [v, w] : adj[u]) {
                if (dist[u] + w < dist[v]) {
                    dist[v] = dist[u] + w;
                    pq.push({dist[v], v});
                }
            }
        }
        int ans = 0;
        for (int i=1;i<=n;i++) ans = max(ans, dist[i]);
        return ans == INT_MAX ? -1 : ans;
    }
};

13

Cheapest Flights Within K Stops

LeetCode 787
Medium

Find the cheapest price from src to dst using at most k stops (i.e. at most k+1 edges), or -1 if not reachable within that limit.

Intuition

Dijkstra optimizes for shortest path with unlimited hops, so it can't respect a hop limit correctly. Bellman-Ford's relax-all-edges-in-rounds structure naturally caps hops: doing exactly k+1 rounds of relaxation guarantees paths use at most k+1 edges.

Approach
  1. dist[] initialized to infinity except dist[src] = 0.
  2. Repeat k+1 times: using a snapshot of dist from the previous round, relax every edge.
  3. The snapshot copy is essential — it stops a single round from chaining multiple hops together.
  4. Return dist[dst], or -1 if still infinity.
Complexity
Time O(k · E)Space O(V)
C++
class Solution {
public:
    int findCheapestPrice(int n, vector<vector<int>>& flights, int src, int dst, int k) {
        vector<int> dist(n, INT_MAX);
        dist[src] = 0;
        for (int i=0;i<=k;i++) {
            vector<int> tmp = dist; // snapshot: caps hops per round
            for (auto& f : flights) {
                int u=f[0], v=f[1], w=f[2];
                if (dist[u] != INT_MAX && dist[u]+w < tmp[v])
                    tmp[v] = dist[u] + w;
            }
            dist = tmp;
        }
        return dist[dst]==INT_MAX ? -1 : dist[dst];
    }
};

14

Min Cost to Connect All Points

LeetCode 1584
Medium

Given points on a 2D plane, connect all of them with edges weighted by Manhattan distance, minimizing total edge cost.

Intuition

The points form a complete graph — this is a pure MST problem in disguise. Prim's algorithm is a natural fit: grow one connected tree by always adding the cheapest edge that reaches a new point.

Approach
  1. Track which points are in the MST with a visited array.
  2. Min-heap of (cost, point), starting from point 0 with cost 0.
  3. Pop the cheapest; if already visited, skip. Otherwise add its cost to the total and mark visited.
  4. Push the Manhattan distance to every unvisited point as a candidate edge.
  5. Stop once all points are visited.
Complexity
Time O(n² log n)Space O(n²)
C++
class Solution {
public:
    int minCostConnectPoints(vector<vector<int>>& pts) {
        int n = pts.size();
        vector<bool> inMST(n, false);
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
        pq.push({0, 0});
        int total = 0, connected = 0;

        while (connected < n) {
            auto [cost, u] = pq.top(); pq.pop();
            if (inMST[u]) continue;
            inMST[u] = true; total += cost; connected++;
            for (int v=0;v<n;v++) {
                if (!inMST[v]) {
                    int d = abs(pts[u][0]-pts[v][0]) + abs(pts[u][1]-pts[v][1]);
                    pq.push({d, v});
                }
            }
        }
        return total;
    }
};

Is Graph Bipartite?

LeetCode 785
Medium

Given an undirected graph as an adjacency list, determine if it's bipartite — nodes can be split into two sets so every edge goes between sets.

Intuition

Try to color every node with one of two colors such that neighbors always differ. If you're ever forced to give a node the same color as a neighbor, the graph isn't bipartite. This is naturally a BFS/DFS with a color array.

Approach
  1. color[] initialized to 0 (uncolored). Iterate every node (graph may be disconnected).
  2. If uncolored, BFS from it, assigning color 1.
  3. For each neighbor: if uncolored, assign the opposite color and continue; if already colored the same as current node, return false.
  4. If every component colors cleanly, return true.
Complexity
Time O(V + E)Space O(V)
C++
class Solution {
public:
    bool isBipartite(vector<vector<int>>& graph) {
        int n = graph.size();
        vector<int> color(n, 0);
        for (int i=0;i<n;i++) {
            if (color[i] != 0) continue;
            queue<int> q; q.push(i); color[i] = 1;
            while (!q.empty()) {
                int u = q.front(); q.pop();
                for (int v : graph[u]) {
                    if (color[v] == 0) { color[v] = -color[u]; q.push(v); }
                    else if (color[v] == color[u]) return false;
                }
            }
        }
        return true;
    }
};

Possible Bipartition

LeetCode 886
Medium

n people, and a list of "dislike" pairs. Split everyone into two groups such that no two people in the same group dislike each other.

Intuition

A "dislike" edge is just a constraint that both endpoints must be in different groups — that's precisely an edge in a bipartite-coloring problem. Build the dislike graph and reuse the exact same 2-coloring approach.

Approach
  1. Build an adjacency list from the dislikes array (1-indexed people).
  2. DFS/BFS coloring exactly as in "Is Graph Bipartite", starting fresh for every uncolored person.
  3. Any color conflict on an edge → return false; otherwise true.
Complexity
Time O(n + d) (d = dislikes)Space O(n + d)
C++
class Solution {
public:
    bool dfs(int u, int c, vector<int>& color, vector<vector<int>>& adj) {
        color[u] = c;
        for (int v : adj[u]) {
            if (color[v] == c) return false;
            if (color[v] == 0 && !dfs(v, -c, color, adj)) return false;
        }
        return true;
    }
    bool possibleBipartition(int n, vector<vector<int>>& dislikes) {
        vector<vector<int>> adj(n+1);
        for (auto& d : dislikes) { adj[d[0]].push_back(d[1]); adj[d[1]].push_back(d[0]); }
        vector<int> color(n+1, 0);
        for (int i=1;i<=n;i++)
            if (color[i]==0 && !dfs(i, 1, color, adj)) return false;
        return true;
    }
};

Word Ladder

LeetCode 127
Hard

Given beginWord, endWord, and a wordList, return the minimum number of words in a transformation sequence from beginWord to endWord, changing one letter at a time.

Intuition

Each word is a node; words differing by exactly one character share an unweighted edge. "Shortest transformation sequence" = "shortest path in unweighted graph" = BFS.

Approach
  1. Store wordList in an unordered_set for O(1) existence checks.
  2. Queue holds (current_word, current_level). Push beginWord with level 1.
  3. For each word popped: try all 26 character replacements for each position. If a replacement exists in the set, erase it (to mark visited) and push it to the queue with level + 1.
  4. If endWord is matched, return its level. If queue empties, return 0.
Complexity
Time O(N · L · 26) (N words of length L)Space O(N · L)
C++
class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        unordered_set<string> words(wordList.begin(), wordList.end());
        if (!words.count(endWord)) return 0;
        queue<pair<string,int>> q;
        q.push({beginWord, 1});
        while (!q.empty()) {
            auto [w, steps] = q.front(); q.pop();
            if (w == endWord) return steps;
            for (int i = 0; i < w.size(); i++) {
                char orig = w[i];
                for (char c = 'a'; c <= 'z'; c++) {
                    w[i] = c;
                    if (words.count(w)) {
                        words.erase(w); // mark visited
                        q.push({w, steps + 1});
                    }
                }
                w[i] = orig;
            }
        }
        return 0;
    }
};

Pacific Atlantic Water Flow

LeetCode 417
Medium

Return all coordinates where water can flow to both the Pacific Ocean (top/left) and Atlantic Ocean (bottom/right), flowing downhill or flat.

Intuition

Checking every cell's path downhill to both oceans is slow. Reverse the flow: start from the ocean borders and flood-fill uphill. The intersection of cells reachable from the Pacific and Atlantic is the answer.

Approach
  1. Create two boolean matrices: pacific[][] and atlantic[][].
  2. Run DFS from Pacific borders (top/left) uphill (heights[nr][nc] >= heights[r][c]).
  3. Run DFS from Atlantic borders (bottom/right) uphill.
  4. Any cell where both matrices are true can flow to both oceans.
Complexity
Time O(R·C)Space O(R·C)
C++
class Solution {
public:
    int R, C;
    int dr[4] = {1,-1,0,0}, dc[4] = {0,0,1,-1};
    void dfs(int r, int c, vector<vector<bool>>& vis, vector<vector<int>>& H) {
        vis[r][c] = true;
        for (int d = 0; d < 4; d++) {
            int nr = r+dr[d], nc = c+dc[d];
            if (nr>=0 && nc>=0 && nr<R && nc<C && !vis[nr][nc] && H[nr][nc] >= H[r][c])
                dfs(nr, nc, vis, H);
        }
    }
    vector<vector<int>> pacificAtlantic(vector<vector<int>>& H) {
        R = H.size(); C = H[0].size();
        vector<vector<bool>> pac(R, vector<bool>(C, false)), atl(R, vector<bool>(C, false));
        for (int r = 0; r < R; r++) { dfs(r, 0, pac, H); dfs(r, C-1, atl, H); }
        for (int c = 0; c < C; c++) { dfs(0, c, pac, H); dfs(R-1, c, atl, H); }
        vector<vector<int>> res;
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                if (pac[r][c] && atl[r][c]) res.push_back({r, c});
        return res;
    }
};

Reconstruct Itinerary

LeetCode 332
Hard

Given a list of flight tickets [from, to], find an itinerary starting at "JFK" that uses every single ticket exactly once in lexicographical order.

Intuition

Using every edge exactly once is finding an Eulerian Path. Hierholzer's algorithm: post-order DFS that consumes edges as it goes, then reversing the output path at the end.

Approach
  1. Build an adjacency map where each airport maps to a min-priority-queue (or multiset) of destinations.
  2. DFS from "JFK": while current airport has unused tickets, pop the lexicographically smallest neighbor and recurse.
  3. When stuck with no edges left, push current airport to the result array (post-order recording).
  4. Reverse the result array before returning.
Complexity
Time O(E log E) (heap sorting per edge)Space O(V + E)
C++
class Solution {
public:
    unordered_map<string, priority_queue<string, vector<string>, greater<string>>> adj;
    vector<string> result;

    void visit(string airport) {
        while (!adj[airport].empty()) {
            string next = adj[airport].top();
            adj[airport].pop();
            visit(next);
        }
        result.push_back(airport);
    }

    vector<string> findItinerary(vector<vector<string>>& tickets) {
        for (auto& t : tickets) adj[t[0]].push(t[1]);
        visit("JFK");
        reverse(result.begin(), result.end());
        return result;
    }
};

Critical Connections in a Network

LeetCode 1192
Hard

Given a connected undirected graph of servers, find all "bridges" — edges whose removal would disconnect the network.

Intuition

This is Tarjan's bridge-finding algorithm. During a DFS, track discovery time of each node and the lowest discovery time reachable from its subtree (via back-edges). An edge (u, v) is a bridge exactly when v's subtree can't reach back to u or anything earlier — low[v] > disc[u].

Approach
  1. DFS from any node, assigning each node a discovery time on first visit.
  2. low[node] starts equal to disc[node], then gets minimized by children's low[] values and back-edges to ancestors.
  3. Skip immediately re-visiting the parent.
  4. After exploring child v from u: if low[v] > disc[u], edge (u, v) is a bridge — record it.
Complexity
Time O(V + E)Space O(V + E)
C++
class Solution {
public:
    vector<vector<int>> adj;
    vector<int> disc, low;
    vector<vector<int>> bridges;
    int timer = 0;

    void dfs(int u, int parentEdge) {
        disc[u] = low[u] = timer++;
        for (int v : adj[u]) {
            if (v == parentEdge) { parentEdge = -1; continue; } // skip one parent edge only
            if (disc[v] == -1) {
                dfs(v, u);
                low[u] = min(low[u], low[v]);
                if (low[v] > disc[u]) bridges.push_back({u, v});
            } else {
                low[u] = min(low[u], disc[v]);
            }
        }
    }

    vector<vector<int>> criticalConnections(int n, vector<vector<int>>& connections) {
        adj.assign(n, {});
        for (auto& c : connections) { adj[c[0]].push_back(c[1]); adj[c[1]].push_back(c[0]); }
        disc.assign(n, -1); low.assign(n, -1);
        dfs(0, -1);
        return bridges;
    }
};

Question 1
You need the shortest path in an unweighted graph. What is the optimal tool?
BFS explores level by level, so the first time it reaches a node is guaranteed to be via the fewest edges — exactly "shortest path" when every edge has equal weight (O(V+E)).
Question 2
Which algorithm is required once edge weights can be negative?
Dijkstra's greedy "closest node is final" assumption breaks with negative weights. Bellman-Ford relaxes all edges repeatedly and correctly handles negatives (and detects negative cycles).
Question 3
Topological sort is only valid on graphs that are:
A cycle would create a contradiction — "A before B before C before A" has no valid linear order. A DAG (Directed Acyclic Graph) is strictly required.
Question 4
In Union-Find, what does "path compression" achieve?
Path compression makes every node on a find() traversal point directly to the root, reducing the tree height and giving nearly O(1) amortized lookups.
Question 5
Rotting Oranges pushes all initially rotten cells into the BFS queue before starting. Why?
All rotten oranges spread at the same time. A multi-source BFS models every "layer" as one minute passing for all of them simultaneously.
Question 6
What is the time complexity of Dijkstra's algorithm using a binary min-heap?
Each edge relaxation can push to the priority_queue (costing O(log V)), giving O((V + E) log V) with a binary heap implementation.
Question 7
In Course Schedule (cycle detection via Kahn's algorithm), how do you know a cycle exists?
Nodes trapped in a cycle never drop to in-degree 0, so they are never enqueued. If the total processed count is less than numCourses, a cycle exists.
Question 8
A "bridge" in a graph (as in Critical Connections) is an edge that:
A bridge is a critical edge whose removal increases the number of connected components because there is no alternative back-edge cycle connecting its endpoints.
Question 9
Prim's algorithm for MST is generally preferred over Kruskal's when the graph is:
Kruskal's sorts all E edges upfront (O(E log E)). Prim's grows outward from vertices and is especially efficient with adjacency matrices/dense complete graphs.
Question 10
Pacific Atlantic Water Flow runs DFS starting from the ocean borders inward rather than from every cell outward. Why?
Flooding inward from the ocean boundaries uphill lets one single DFS pass mark all cells capable of reaching that ocean in O(R·C) time.
