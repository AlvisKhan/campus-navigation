5.1

Learning Algorithms

Before anything is "deep," it's a learning algorithm — something that gets better at a task by using data. This section pins down exactly what that means.

Tom Mitchell's classic definition: a program learns from experience E with respect to task T and performance measure P, if its performance on T, measured by P, improves with E. Every learning system you'll ever study is really just a specific choice of these three ingredients.

The Task, T

The task is never "learning" itself — learning is the means, not the end. Common tasks: classification, regression, transcription, machine translation, anomaly detection, density estimation. An input is represented as a feature vector \(\boldsymbol{x} \in \mathbb{R}^n\), where each entry is one measured attribute of the example (e.g. one pixel's brightness).

The Performance Measure, P

P is a task-specific, quantitative yardstick — accuracy for classification, or average log-probability for density estimation. The number that actually matters is performance on new, unseen data (a test set), not on the data the model trained on — otherwise a model could just memorize.

The Experience, E

Most algorithms experience an entire dataset. This splits learning into two broad families:

  • Unsupervised learning — the dataset has features only; the algorithm must find structure on its own (e.g. clustering, or learning the whole probability distribution \(p(\boldsymbol{x})\)).
  • Supervised learning — each example is paired with a label or target; the algorithm learns to predict the target from the features, i.e. \(p(y \mid \boldsymbol{x})\).
Intuition

The supervised/unsupervised line is blurry, not fundamental — you can always factor a joint distribution into conditionals via the chain rule, turning an "unsupervised" density-estimation problem into a sequence of supervised ones, and vice versa. Reinforcement learning sits outside this dataset-with-a-fixed-distribution picture entirely: the experience comes from interacting with an environment.

Worked example: Linear Regression

Linear regression takes a vector \(\boldsymbol{x}\) and predicts a scalar \(y\) as a linear function of the input:

Model
\[\hat{y} = \boldsymbol{w}^\top \boldsymbol{x}\]

Here \(\boldsymbol{w} \in \mathbb{R}^n\) is the vector of learned weights. We measure performance on a test set via mean squared error:

Performance measure
\[\text{MSE}_{\text{test}} = \frac{1}{m}\sum_i (\hat{\boldsymbol{y}}^{(\text{test})} - \boldsymbol{y}^{(\text{test})})_i^2\]

Training means picking \(\boldsymbol{w}\) to minimize \(\text{MSE}_{\text{train}}\). Because MSE is a smooth, convex quadratic in \(\boldsymbol{w}\), setting its gradient to zero gives a closed-form solution — the normal equations:

Closed-form solution
\[\boldsymbol{w} = \left(\boldsymbol{X}^{(\text{train})\top}\boldsymbol{X}^{(\text{train})}\right)^{-1}\boldsymbol{X}^{(\text{train})\top}\boldsymbol{y}^{(\text{train})}\]
Why it matters

Linear regression is the simplest possible instance of the T / P / E recipe — and it's the seed every later model in the book grows from: add a nonlinearity and stack a few of these together, and you have a neural network layer.

5.2

Capacity, Overfitting & Underfitting

The single most important idea in the whole chapter: a model's real job is generalization — doing well on inputs it never trained on.

We assume train and test data are drawn independently from the same underlying distribution — the i.i.d. assumption. This lets us reason about a model's generalization (test) error even though we can only directly optimize its training error.

A model's capacity is, loosely, how wide a variety of functions it's able to represent. Two failure modes bracket every model:

  • Underfitting — capacity too low to even get the training error down. The model can't capture the true pattern.
  • Overfitting — the gap between training and test error is too large. The model has partly memorized the training set's noise instead of learning the general pattern.

The No Free Lunch Theorem

Averaged over every possible data-generating distribution, every classification algorithm achieves the same test error on unseen points — no algorithm is universally better. In practice this isn't discouraging: we don't care about every conceivable universe, only the distributions that resemble the real world, and for those, some algorithms genuinely do better than others.

Regularization

Rather than only adding/removing functions from a model's hypothesis space, we can express a preference for some functions over others. Weight decay is the classic example: add \(\lambda \boldsymbol{w}^\top \boldsymbol{w}\) to the training objective so the optimizer trades off fitting the data against keeping weights small.

Common pitfall

Regularization is not "reducing capacity" in a simple counting sense. A degree-9 polynomial with strong weight decay still has 9 coefficients — but the effective family of functions it will realistically settle on is far smaller and smoother than its raw representational capacity would suggest.

5.3

Hyperparameters & Validation Sets

Some settings can't be learned by the training algorithm itself — they have to be chosen from outside it.

Hyperparameters control the model or algorithm's behavior (e.g. polynomial degree, or the weight-decay coefficient \(\lambda\)). We can't just learn them by minimizing training error the normal way — the optimizer would always pick maximum capacity and zero regularization, guaranteeing overfitting.

The fix: carve a validation set out of the training data (never the test set) that the training algorithm never sees directly. Hyperparameters are tuned to minimize error on this held-out slice, typically ~80/20 train/validation.

Common pitfall

The test set must stay completely untouched during model/hyperparameter selection. The moment you tune anything based on test performance, your test error stops being an honest estimate of generalization — you've effectively turned the test set into a validation set.

Cross-Validation

When a dataset is too small to reserve a stable validation split, k-fold cross-validation partitions the data into k folds, trains k times (holding out a different fold each time), and averages the test error across folds — trading extra compute for a lower-variance error estimate.

5.4

Estimators, Bias and Variance

Statistics gives us precise vocabulary for why a model over- or under-fits: bias and variance.

Point Estimation & Bias

A point estimator \(\hat{\boldsymbol\theta}_m\) is any function of m data samples that tries to approximate a true parameter \(\boldsymbol\theta\). Its bias is:

Bias of an estimator
\[\text{bias}(\hat{\boldsymbol\theta}_m) = \mathbb{E}[\hat{\boldsymbol\theta}_m] - \boldsymbol\theta\]

An estimator is unbiased when this is exactly zero. The sample mean is an unbiased estimator of a Gaussian's true mean; the sample variance \(\frac{1}{m}\sum (x_i-\hat\mu)^2\) is actually biased — dividing by \(m-1\) instead fixes it.

Variance & Standard Error

Variance measures how much the estimate would fluctuate if you re-ran training on a different sample from the same distribution. Low variance means the estimator is stable across datasets; high variance means it's sensitive to the specific data it happened to see.

The Bias-Variance Tradeoff

Bias and variance measure two different sources of error, and they trade off against each other as capacity changes:

Mean squared error decomposition
\[\text{MSE} = \text{bias}(\hat\theta_m)^2 + \text{Var}(\hat\theta_m)\]
Dartboard analogyBeyond the book

Not in the original text — but this is the fastest way anyone learns bias vs. variance. The bullseye is the true parameter; each dart is one trained model's estimate from one dataset.

5.5

Maximum Likelihood Estimation

Where do "good" estimators like MSE actually come from? MLE is the principle that derives most of them from first principles.

Given data \(\mathbb{X}=\{\boldsymbol x^{(1)},\dots,\boldsymbol x^{(m)}\}\) drawn i.i.d. from the true (unknown) distribution \(p_{\text{data}}\), and a family of candidate distributions \(p_{\text{model}}(\boldsymbol x;\boldsymbol\theta)\), the maximum likelihood estimator picks the \(\boldsymbol\theta\) that makes the observed data most probable:

Maximum likelihood estimator
\[\boldsymbol\theta_{\text{ML}} = \arg\max_{\boldsymbol\theta} \sum_{i=1}^m \log p_{\text{model}}(\boldsymbol x^{(i)}; \boldsymbol\theta)\]

Taking logs turns a product of probabilities into a sum (numerically stable, easier to differentiate) without changing the arg max. Dividing by \(m\) reframes this as minimizing the KL divergence between the empirical data distribution and the model — i.e. MLE is exactly the estimator that pulls the model distribution as close as possible to the true data distribution.

Intuition

Under a Gaussian noise assumption, maximizing likelihood for a regression model turns out to be mathematically identical to minimizing mean squared error. MSE wasn't an arbitrary choice — it falls straight out of MLE with a Gaussian assumption.

Properties of Maximum Likelihood

Under mild conditions, MLE is the consistent estimator with the best possible convergence rate as the number of examples grows — which is exactly why it's the default starting point for so many estimators in machine learning.

5.6

Bayesian Statistics

MLE treats the true parameter as one fixed unknown number. Bayesian statistics treats it as a whole distribution of belief.

Before seeing any data, we specify a prior distribution \(p(\boldsymbol\theta)\) — typically fairly high-entropy, reflecting genuine uncertainty. After observing data, Bayes' rule combines the prior with the likelihood to get a posterior:

Bayes' rule for parameters
\[p(\boldsymbol\theta \mid \boldsymbol x^{(1)},\dots,\boldsymbol x^{(m)}) \propto p(\boldsymbol x^{(1)},\dots,\boldsymbol x^{(m)} \mid \boldsymbol\theta)\, p(\boldsymbol\theta)\]

Two practical differences from MLE matter a lot:

  • Predictions are made by averaging over the full posterior rather than plugging in a single point estimate — this naturally reduces overfitting on small datasets, since uncertainty in \(\boldsymbol\theta\) is propagated into the prediction.
  • The prior lets you inject useful bias, e.g. preferring simpler or smoother models before seeing any data — which is precisely how weight decay can be re-derived as a Gaussian prior on the weights.

Maximum A Posteriori (MAP) Estimation

Fully Bayesian inference is often too expensive for high-dimensional \(\boldsymbol\theta\). MAP is a practical compromise: still use a prior, but collapse the posterior back down to a single point estimate at its peak:

MAP estimate
\[\boldsymbol\theta_{\text{MAP}} = \arg\max_{\boldsymbol\theta} \log p(\boldsymbol x \mid \boldsymbol\theta) + \log p(\boldsymbol\theta)\]
Why it matters

Weight decay is not a separate ad-hoc trick — it is exactly the log-prior term you get from putting a zero-mean Gaussian prior on the weights and doing MAP estimation. Regularization and Bayesian priors are the same idea wearing two different names.

5.7

Supervised Learning Algorithms

Four classic non-deep algorithms — worth knowing because deep learning was built explicitly to overcome their limits.

Logistic Regression

Despite the name, this is a classifier. It squashes a linear function through the logistic sigmoid to output a valid probability:

Binary logistic regression
\[p(y=1 \mid \boldsymbol x;\boldsymbol\theta) = \sigma(\boldsymbol\theta^\top \boldsymbol x)\]

Unlike linear regression, there's no closed form — it's trained by numerically maximizing likelihood (gradient-based search).

Support Vector Machines (SVM)

Similar to logistic regression — driven by a linear function \(\boldsymbol w^\top\boldsymbol x + b\) — but outputs a hard class identity, not a probability. Its key trick: the decision function can be rewritten purely in terms of dot products between examples:

Kernelized decision function
\[f(\boldsymbol x) = b + \sum_i \alpha_i\, k(\boldsymbol x, \boldsymbol x^{(i)})\]

This is the kernel trick: replace the dot product with a kernel function \(k\) and you get a decision boundary that's nonlinear in x while the underlying optimization stays convex and efficient. The most common choice, the Gaussian / RBF kernel, effectively does template-matching against training examples. The cost: prediction time scales with the number of support vectors (nonzero \(\alpha_i\)), which grows with dataset size — a limitation deep networks were designed to avoid.

k-Nearest Neighbors

A genuinely non-parametric method — no training phase at all. At test time, find the k closest training points and average their targets. Capacity is essentially unbounded (it grows with the dataset), but it can't tell which input features actually matter, so it degrades badly when most features are irrelevant noise.

Decision Trees

Recursively splits input space into axis-aligned boxes; each leaf outputs a constant. Cheap and interpretable, but decision boundaries that aren't axis-aligned (e.g. a diagonal line) require many nodes to approximate — a structural weakness plain logistic regression doesn't have.

5.8

Unsupervised Learning: PCA

Unsupervised algorithms find structure in unlabeled data. Principal Components Analysis is the clearest classic example: it learns a representation.

PCA finds a linear, orthogonal transformation \(\boldsymbol z = \boldsymbol x^\top \boldsymbol W\) of the data such that the new coordinates \(\boldsymbol z\) are decorrelated — no linear relationship remains between any two output dimensions. The new axes are chosen to align with the directions of greatest variance in the original data.

Formally, PCA diagonalizes the covariance matrix of the data: it finds the rotation \(\boldsymbol W\) (the matrix of eigenvectors of \(\text{Var}[\boldsymbol x]=\frac{1}{m-1}\boldsymbol X^\top\boldsymbol X\)) such that the covariance of \(\boldsymbol z\) is diagonal — i.e. its dimensions are uncorrelated. This makes PCA a simple, effective dimensionality-reduction and feature-decorrelation tool, and a first step (though not a complete solution) toward learning fully statistically independent representations.

5.9

Stochastic Gradient Descent

The optimization workhorse behind almost every deep learning model ever trained.

Ordinary gradient descent needs the gradient of the cost summed over the entire training set at every step — for a dataset with millions of examples, that's prohibitively slow per update. The cost function for most ML models decomposes as a sum/average over per-example losses, so its gradient is itself an average over per-example gradients:

Gradient of the cost
\[\nabla_{\boldsymbol\theta}\, J(\boldsymbol\theta) = \frac{1}{m}\sum_{i=1}^m \nabla_{\boldsymbol\theta}\, L(\boldsymbol x^{(i)}, y^{(i)}, \boldsymbol\theta)\]

Stochastic (minibatch) gradient descent approximates this average using a small, randomly-sampled minibatch of examples (often 1 to a few hundred) instead of the whole dataset, then updates:

SGD update rule
\[\boldsymbol\theta \leftarrow \boldsymbol\theta - \epsilon\, \boldsymbol g \qquad \text{where } \boldsymbol g = \frac{1}{m'}\sum_{i=1}^{m'} \nabla_{\boldsymbol\theta}\, L(\boldsymbol x^{(i)}, y^{(i)}, \boldsymbol\theta)\]

where \(\epsilon\) is the learning rate. Because each step's cost no longer scales with total dataset size, SGD lets training cost grow with model complexity rather than with the size of the training set — the property that makes training on today's massive datasets computationally feasible at all.

Why it matters

SGD isn't just an optimizer — the book flags it as one of the handful of ingredients (alongside distributed/large datasets and flexible model families) that make modern deep learning practical at all.

5.10

Building a Machine Learning Algorithm

Nearly every algorithm in this book — deep or shallow — is built from the same four interchangeable Lego bricks.

  1. A dataset — the experience E.
  2. A cost function — typically a data term (e.g. negative log-likelihood) plus a regularization term.
  3. An optimization procedure — closed-form solving where possible, otherwise iterative methods like SGD.
  4. A model — the family of functions being searched over, e.g. linear, or (later in the book) a deep network.

Swap the model from linear to a neural net, and the cost from linear regression's MSE to negative log-likelihood, and the same recipe assembles logistic regression. Swap the optimizer from closed-form to SGD and you get most of modern deep learning. Recognizing these four pieces in any new algorithm is often the fastest way to actually understand it.

5.11

Challenges Motivating Deep Learning

Why wasn't 1990s-style shallow machine learning enough? Three structural problems — and deep learning's answer to each.

The Curse of Dimensionality

Many algorithms behave well when the number of relevant variables is small, then degrade sharply as dimensionality grows. The number of distinct regions you need to distinguish grows exponentially with dimension.

Local Constancy & Smoothness Regularization

Most traditional algorithms implicitly rely on a smoothness prior (a.k.a. local constancy): the learned function shouldn't change much within a small neighborhood, so a new point can be predicted mainly from nearby training points. This works fine in low dimensions but breaks down once you need to distinguish exponentially many regions — you simply can't have a training example in every neighborhood. Deep architectures instead encode much stronger, more targeted priors (e.g. convolutional weight-sharing, distributed representations) that let them generalize well without needing that dense local coverage.

Manifold Learning

Real-world high-dimensional data (images, audio) is not spread uniformly through its raw coordinate space — it concentrates near a much lower-dimensional manifold embedded in that space. E.g. among all possible pixel-grids, only a tiny sliver look like plausible photographs; random pixel noise almost never resembles a real image. The manifold hypothesis — that the data of interest lies on such a low-dimensional manifold — is a key structural assumption that lets deep learning avoid a literal fight with the curse of dimensionality: the model only needs to be accurate on (and near) the manifold, not everywhere in the ambient space.

Cheat Sheet

One line each — the chapter compressed for a five-minute pre-exam skim.

Task · Perf · Experience

Every learner = a task T, a performance measure P, and an experience E (supervised = has labels, unsupervised = doesn't).

Capacity

Too low → underfits. Too high → overfits. Sweet spot minimizes the gap between train and test error.

Regularization

Express a preference over functions (e.g. weight decay) rather than just restricting the hypothesis space.

Validation set

A slice of training data used to pick hyperparameters — never touch the test set for this.

Bias vs. Variance

Bias = systematically wrong on average. Variance = wildly different across resamples. MSE = bias² + variance.

MLE

Pick parameters that make the observed data most probable — MSE for regression falls out of MLE + Gaussian noise.

Bayesian / MAP

Keep a full posterior over parameters (Bayesian) or its peak (MAP). Weight decay = Gaussian prior + MAP.

SVM / kernel trick

Rewrite a linear model with dot products, swap in a kernel → nonlinear boundary, convex optimization.

k-NN & decision trees

Non/semi-parametric, carve input space into regions; both struggle outside axis-aligned or locally-smooth structure.

PCA

Linear rotation that decorrelates features and concentrates variance in the first few dimensions.

SGD

Estimate the true gradient from a small random minibatch — makes training cost independent of dataset size.

Curse of dimensionality

Regions needed grow as O(v^d). The manifold hypothesis is deep learning's escape hatch.
