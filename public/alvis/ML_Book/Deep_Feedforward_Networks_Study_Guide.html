§6.0

What is a feedforward network, really?

Before any equations: the one-sentence idea, the vocabulary you'll need for the rest of the chapter, and why the field ended up calling this whole family "deep learning."

A feedforward network is a function-approximation machine. It's handed some input x and asked to output something close to the true, unknown target y = f*(x) — a category for a photo, a price for a house, whatever the task needs. The network itself computes y = f(x; θ), and training is the process of nudging the parameters θ until f imitates f* closely.

The "feedforward" part is a topology claim: information moves strictly forward — input → intermediate computations → output — with no path that loops a later value back into an earlier computation. The moment you add that kind of loop, you've left this chapter and entered recurrent networks (Chapter 10).

Structurally, these models are chains of functions: f(x) = f⁽³⁾(f⁽²⁾(f⁽¹⁾(x))). Each link in the chain is a layer. The number of links is the network's depth — the word that literally gave "deep learning" its name. The width of a layer is just the dimensionality of the vector it outputs.

Why "hidden"The training data tells the network exactly what the final, output layer should produce. It says nothing about what any interior layer should compute — the optimizer has to invent useful intermediate representations on its own. Since the desired values for those layers are never observed, they're "hidden."

"Neural" is the loosest word in the name. Each hidden layer is a vector, and each entry behaves a bit like a neuron: it takes many inputs and produces one activation. But the field is guided far more by math and engineering than by neuroscience these days — think of these as function approximators that occasionally borrow a metaphor from biology, not brain simulators.

Three ways to get a nonlinear feature map

Linear models are easy to fit but can't capture interactions between input variables. The fix is to apply a linear model not to x directly but to some transformed φ(x). The whole chapter is really about how to pick φ:

StrategyHowTrade-off
Generic φe.g. the infinite-dimensional map implicit in an RBF kernelEnough capacity to fit training data, but weak inductive bias → often generalizes poorly
Hand-engineered φDomain experts design features (classic pre-2012 pipeline)Works well but needs years of specialist effort per task, little transfer
Learned φy = φ(x;θ)w — a hidden layer is φ, learned jointly with the output weights wGives up convexity of the training problem, but the flexibility more than pays for it

That third row is deep learning's whole strategy in one line, and it's the thread every later section pulls on.

§6.1

Learning XOR — drive the network yourself

The book's smallest possible example, but it's the one that shows why a hidden layer is necessary at all. Toggle the two inputs below and watch every number in the forward pass update live.

XOR outputs 1 when exactly one input is 1, and 0 otherwise. It's a tiny dataset — only four points — but a plain linear model f(x;w,b) = xw + b cannot represent it. Solve the normal equations and you get w = 0, b = 0.5: the "best" linear model just outputs 0.5 everywhere, which is wrong on all four points. Geometrically, the two positive examples and the two negative examples can't be separated by any straight line in x-space.

The fix is to first warp the input into a new space where a straight line does work. That warp is exactly what a hidden layer computes: h = g(Wx + c), followed by a linear output ŷ = w·h + b. Crucially, g must be nonlinear — stack two linear layers and the composition is still just one linear function, so nothing is gained.

The book hand-picks a solution using ReLU, g(z) = max(0, z), that reaches zero training error exactly:

The hand-picked weights W = [[1,1],[1,1]],   c = [0, −1],   w = [1, −2],   b = 0

What ReLU does here is fold the input space: after the transform, the two points that must output 1 — (1,0) and (0,1) — get mapped onto the same point in hidden space, while the two points that must output 0 land elsewhere. Once they coincide, a single linear read-out can separate them from the rest.

§6.2

Cost functions & output units

Training a network needs three ingredients: an optimizer, a cost function, and an output representation. The chapter's real insight is that the last two are joined at the hip.

Almost every modern network is trained by maximum likelihood: define a conditional distribution p(y|x;θ) and minimize its negative log-likelihood, i.e. the cross-entropy between the data and the model. This single recipe removes the chore of hand-designing a bespoke loss for every architecture — pick the output distribution, and the cost function falls out automatically.

One recurring worry in network design: the gradient has to stay large enough to actually guide learning. Activation functions that saturate (go flat) starve the optimizer of signal. Cross-entropy is popular precisely because its log tends to cancel the exp buried inside common output units, undoing that saturation — mean squared error offers no such cancellation.

Three standard output units

UnitDistributionFormulaUse it for
LinearGaussianŷ = Wh + bPredicting a real-valued mean; doesn't saturate, plays nicely with any optimizer
SigmoidBernoulliŷ = σ(wᵀh + b)Binary classification; always pair with cross-entropy, never raw thresholding
SoftmaxMultinoullisoftmax(z)ᵢ = exp(zᵢ)/Σⱼexp(zⱼ)k-way classification; a direct generalisation of the sigmoid

A subtlety worth internalising: softmax is shift-invariant — softmax(z) = softmax(z + c) for any constant c — which is exactly what lets you subtract max(z) before exponentiating for numerical stability without changing the answer. And when maximum likelihood trains a softmax, the negative-log-likelihood gradient with respect to the logits collapses to the strikingly simple qᵢ − pᵢ (predicted minus true probability) — one of the rare cases where a human can spot a simplification that plain backprop, applied mechanically, would never find on its own.

§6.3

Hidden units — the activation function zoo

There's no grand theory for which activation to use — this is one of the most trial-and-error corners of network design. But a few defaults and a few cautionary tales dominate practice.

ReLU, g(z) = max(0, z), is the default. It behaves like a linear unit everywhere it's active, so gradients stay large and consistent instead of shrinking — the second derivative is zero almost everywhere, so there's no curvature to fight. Its one weakness: a unit that's stuck outputting zero gets no gradient at all. That motivates a family of generalisations that keep a nonzero slope α below zero: g(z) = max(0,z) + α·min(0,z).

  • Absolute value rectification — fixes α = −1, giving g(z) = |z|. Useful when you want invariance to a flipped sign in the input.
  • Leaky ReLU — fixes α to a small constant like 0.01.
  • Parametric ReLU (PReLU) — makes α itself a learned parameter.
  • Maxout — the most general: splits the pre-activations into groups of k and outputs the max of each group, effectively learning a piecewise-linear activation shape (up to k pieces) instead of fixing one in advance. Needs more regularisation since each unit now owns k weight vectors.

Sigmoid and tanh dominated the 1980s–2000s but saturate across almost their whole domain, which chokes gradient-based learning — they're now discouraged as hidden units (sigmoid remains fine as an output unit paired with cross-entropy, where the saturation gets cancelled). If you must use a sigmoidal hidden unit, prefer tanh: since tanh(0)=0 while σ(0)=0.5, tanh behaves more like the identity near the origin, which keeps early training closer to a well-behaved linear model.

Counterintuitive resultSoftplus, ζ(a) = log(1+eᵃ), is a smooth version of ReLU — differentiable everywhere, saturates less. You'd expect it to beat plain ReLU. Empirically it doesn't. It's a good reminder that intuitions about activation functions need to be checked against experiments.

§6.4

Architecture design: depth vs. width

Once you've chosen a hidden unit type, you still have to decide how many layers and how many units per layer — and whether "layers" even has to mean "one long chain."

The universal approximation theorem (Hornik et al. 1989; Cybenko 1989) is often misquoted. What it actually says: a feedforward network with one hidden layer, a squashing (or ReLU-like) activation, and enough hidden units can approximate any well-behaved (Borel measurable) function to any desired accuracy. What it does not say:

  • How large "enough" is — in the worst case it can be exponential in the input dimension.
  • That an optimizer will actually find those parameters.
  • That the learned function will generalize to unseen data.

So the theorem guarantees representability, not learnability or generalization — those are separate battles.

Why go deep instead of just wide?

Montúfar et al. (2014) showed that a deep rectifier network can carve the input space into a number of distinct linear regions that grows exponentially with depth, while a shallow network with a comparable unit count grows only polynomially. Intuitively: each layer can "fold" the space (much like an absolute-value unit mirrors its input around a hyperplane), and composing many folds multiplies the number of regions rather than adding to it.

This isn't just theory. Empirically, on tasks like transcribing multi-digit numbers from photographs, test accuracy climbs steadily as depth increases from a few layers to ten-plus — and a separate control shows that simply adding more parameters to a shallow network does not reproduce the same gain. Depth itself is doing the work.

Choosing a deep model is really a statement of prior belief: that the target function is naturally a composition of simpler sub-functions (edges → corners → shapes → objects), or a multi-step program where each step reuses the last one's output.

Beyond simple chains

Real architectures often deviate from a pure chain: skip connections feed layer i's output directly into layer i+2 or beyond, giving gradients a shorter path back to early layers. Sparse connectivity — where each unit only sees a subset of the previous layer — cuts parameters and computation dramatically; convolutional networks (Chapter 9) are the canonical example.

§6.5

Backpropagation, one value at a time

Backprop is not a learning algorithm — it's a bookkeeping trick for computing a gradient without paying an exponential price. Here's the trick, made concrete.

Every network computation can be drawn as a computational graph: nodes are variables, edges are operations. The chain rule lets you compute the derivative of an output with respect to any node feeding into it — for scalars, dz/dx = (dz/dy)(dy/dx); for vectors/tensors, that becomes a sum over a Jacobian.

The trap: applying the chain rule naively and recursively can recompute the same sub-expression exponentially many times as a graph gets deep. Backprop avoids this with dynamic programming — it fills a table of already-computed values once, in reverse topological order, and every later computation just looks up what it needs instead of recomputing it. That's the entire trick.

Important distinctionBackprop only computes the gradient. A separate algorithm — typically stochastic gradient descent — actually uses that gradient to update the parameters. "Backprop" and "the learning algorithm" are not the same thing, even though people often say "backprop" to mean the whole training loop.

Two implementation philosophies exist: symbol-to-number differentiation plugs in numeric values and returns numeric gradients directly (e.g. classic Torch/Caffe); symbol-to-symbol differentiation instead builds new graph nodes that symbolically describe the gradient computation (Theano/TensorFlow-style) — which has the nice side effect that you can differentiate the derivative again, straightforwardly getting higher-order derivatives.

Cost-wise, for a graph with n nodes, backprop never needs more than O(n²) operations in general, and for the roughly chain-structured graphs typical of neural network cost functions, the real cost is closer to O(n) — about one Jacobian–vector product per edge, computed exactly once.

§6.6

How we got here

The math in this chapter is mostly decades old. What actually changed performance since the 1980s is a short list — and it's worth knowing which two items are on it.

1670s
Leibniz and later L'Hôpital formalise the chain rule — the mathematical seed of backprop, three centuries early.
1847
Cauchy introduces gradient descent as an iterative way to approximate optimization solutions.
1940s–50s
Early linear models like the perceptron emerge; Minsky and others point out they provably cannot learn XOR, triggering a backlash against neural networks.
1960s–70s
Efficient chain-rule bookkeeping (dynamic-programming style) appears in control theory and sensitivity analysis — the technical precursor to backprop.
1986
Rumelhart, Hinton & Williams popularise backpropagation for training multilayer networks; the Parallel Distributed Processing book ignites a wave of connectionist research.
Early 1990s
Neural network research peaks, then loses ground to other machine learning methods for over a decade.
2006
The modern deep learning renaissance begins — though feedforward nets are initially still seen as needing help from probabilistic models.
~2009–2011
Jarrett et al. and Glorot et al. show rectified linear units outperform sigmoid hidden units — one of the two big algorithmic wins of the era, alongside cross-entropy replacing MSE as the standard loss.
2012 →
Feedforward, gradient-based learning stops being "the thing other models lean on" and becomes a powerful tool in its own right — later even powering generative models like VAEs and GANs.

Zoom out and the field's own retrospective is refreshingly humble: the core algorithm hasn't changed much since the 1980s. What actually moved performance from 1986 to the mid-2010s breaks down to roughly:

  1. Bigger datasets, which reduced how much generalization had to be squeezed out of clever modeling.
  2. Bigger networks, enabled by faster hardware and better software infrastructure.
  3. Two specific algorithmic swaps: mean squared error → cross-entropy loss, and sigmoid hidden units → piecewise-linear units like ReLU.

Interesting footnote: rectification itself is not new — it traces back to the Cognitron/Neocognitron in the 1970s–80s. It fell out of favor for decades partly on a now-debunked worry that non-differentiable points (like ReLU's kink at zero) would break gradient-based training in practice. They don't, because training almost never lands exactly on that single point, and one-sided derivatives are a perfectly serviceable convention when it does.
