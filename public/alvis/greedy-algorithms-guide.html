Interview Field Guide

Take the best coin right now — worry about the rest later.

A hands-on, visual walkthrough of greedy algorithms: when the locally best choice actually leads to a globally optimal answer, when it doesn't, and how to spot the difference in an interview.

01 — The Idea

What actually makes an algorithm "greedy"?

At every step, a greedy algorithm makes the choice that looks best right now — without reconsidering it later — and hopes that a sequence of good local choices adds up to a good global result. It never backtracks.

Making change — you owe someone 67¢. You grab the biggest coin that still fits (a quarter), then the next biggest, and so on. You never once reconsider an earlier coin.
Packing a bag by value density — you grab the item worth the most per kilogram first, and keep going until you run out of room.
Scheduling — of all the meetings still available, you always book the one that frees your calendar up soonest.

1 Greedy-choice property

A globally optimal solution can be reached by choosing the locally optimal option at each step — you never have to look back and undo a choice.

2 Optimal substructure

An optimal solution to the full problem contains optimal solutions to its subproblems. (Greedy shares this property with Dynamic Programming.)

3 No backtracking

This is what makes greedy fast — usually O(n log n), dominated by a sort — but it's also exactly why it fails on problems that don't have property #1.

02 — The Interview Question Behind The Question

Greedy, or dynamic programming?

This is the real decision an interviewer is testing. Both need optimal substructure — the split is the greedy-choice property.

Signal
Greedy tends to work
You probably need DP
Choice reversibility
A choice, once made, is never revisited
An early choice might need to be undone later
Subproblem overlap
Each step shrinks to one clean remaining subproblem
Subproblems overlap and get recomputed
Proof style
Exchange argument holds (swap in the greedy choice, solution doesn't get worse)

Typical complexity
O(n log n) — sort, then one linear pass
O(n·k) or O(n²) — a table of subproblem answers
Classic tell
"Maximum non-overlapping…", "minimum coins (canonical)…", "assign / schedule to minimize/maximize…"
"Count the ways…", "minimum over all combinations…", denominations not guaranteed canonical
The exchange argument, in one breath

To prove greedy is correct, take any optimal solution that disagrees with the greedy choice at step 1, and show you can swap the greedy choice into it without making it worse. If that swap always works, greedy is provably optimal — that's the proof interviewers actually want to hear, even in one sentence.

03 — Pattern Recognition

Six shapes greedy problems come in

Most interview greedy problems reduce to one of these. Recognize the shape, recall the sort key.

01

Interval scheduling

Sort by end time. Take an interval if it starts after the last one you took ends.

02

Ratio maximization

Sort by value-per-unit-cost. Take the highest ratio first until you're out of budget.

03

Merging by frequency

Repeatedly combine the two smallest weights first (priority queue). Huffman coding, connecting ropes.

04

Deadline / slot assignment

Sort by value descending, place each item in the latest free slot it still qualifies for.

05

Two-pointer trade-off

Sort ascending and descending together — pairing smallest-with-largest. Boat capacity, candy distribution.

06

Running feasibility

Track a running resource (fuel, balance) left-to-right; greedily refuel/reset only when it goes negative.

Pattern 02

Fractional Knapsack

O(n log n) Ratio Maximization

Given items with weight and value, and a knapsack of capacity W, maximize total value — items can be split into fractions. Greedy rule: sort by value/weight ratio descending, take as much of the best ratio as will fit. (Note: the 0/1 version, where items can't be split, needs DP instead — this is the classic trap.)

05 — Before You Walk In

The 60-second cheat sheet

How to recognize a greedy problem

  • Words like "maximum non-overlapping", "minimum number of…", "earliest / latest"
  • A natural sort key jumps out (finish time, ratio, deadline, profit)
  • Each decision, once made, never needs to be revisited

How to justify it out loud

  • State the greedy rule in one sentence
  • Give the exchange-argument intuition (swap greedy choice into any optimal solution)
  • Name the complexity — usually dominated by the initial sort

Red flags that greedy will fail

  • Items can't be split (0/1 constraint) but you were about to sort by ratio
  • Coin/denomination set isn't stated as canonical
  • You can construct a counterexample where reordering beats greedy

Fallback when greedy doesn't hold

  • Dynamic programming — define the subproblem, find the recurrence
  • Check optimal substructure still holds even if greedy-choice doesn't
  • Say this explicitly — recognizing the failure is the point being tested
